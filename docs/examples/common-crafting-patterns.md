# 常见打造模式：概念、资格与覆盖边界

状态：概念、资格与已执行参考校验，2026-11-03。数值仅在声明的参考模型下成立，不代表游戏客户端制作实测。FP、原子操作与退款依据[动作审计](../research/affix-actions-audit.md)和[费用审计](../research/forge-fp-audit.md)；路线停止规则见[宏动作契约](../macro-actions.md)。

## 1. 短记号与共同假设

771x 只表示普通未封印栏的阶数信息；0 是空栏，不是一条 T0 词缀。它不表示词缀身份、前后缀侧别或原生列表顺序，也不包括普通封印、先古 T8 封印等额外槽。每个研究案例必须另外固定底材、实际 ID、侧别、原生顺序、角色等级、FP 类型及各阶段支持物。

A、B 是目标 ID；终局要求二者都处于普通未封印栏且各恰好 T7。垃圾指不属于 A／B、未受明确保护且符合对应动作原生资格的对象，并非所有非目标词缀都自动可以封印或剥离。

材料固定无限，没有价格、库存和材料消耗上限。FP 仍有限，按公开假设预算评价。每个必要封印只试一次，失败即终止整条路线；失败原生后处理和已花 FP仍计入该失败叶。浩劫、救赎按事先声明的宏条件重试，不要求玩家回填。

## 2. 身份已齐全：最终浩劫优先基线

先检查 A、B 是否已存在于普通未封印栏。若身份已齐、尚未各达到 T7，且四栏与其他原生资格允许，优先生成：

~~~text
FINAL_HAVOC_UNTIL(A@ordinaryT7 AND B@ordinaryT7)
~~~

例如 7732 的两条 T7 都可能是垃圾，而 A@T3、B@T2 已经存在。这是身份已齐的 77tu 阶数重排案例，不属于“所有目标都缺”；不能重复添加 A／B 或强迫先救赎搜身份。若终局目标原本已满足，则空路线即可。

“两条 T7 都不是所需”与“四条词缀 ID 全都不是所需”必须分别表达。阶数多重集不能代替真实 ID 检查。此处只有优先基线，不预断它优于任何另有合法准备步骤的路线。

## 3. 已有 A@T7、缺 B：四栏 771x

这是用户最常见模式。A 已是现有 T7 中的一条；B 尚未存在，普通封印槽空。入口确有四条普通未封印词缀，x 必须逐例取实际值 1…7。

| x | 需要保留的边界 |
|---|---|
| x=1 | 有两条 T1；按 B 所需侧、垃圾资格及保护条件过滤，再取最低原生列表序号，不任意假定其中一条 |
| x=2…6 | 与 T1 不同的另一垃圾阶数逐值保留，候选和费用核不能混为统一未知 x |
| x=7 | 一共三个 T7，是有效边界；不能把它裁掉或套用两 T7 布局的概率 |

### 3.1 垃圾 T1 已在 B 所需侧

~~~text
SEAL_ONCE(该侧可封垃圾T1，最低原生序，排除A/B/保护对象)
ADD_B
FINAL_HAVOC_UNTIL(A@ordinaryT7 AND B@ordinaryT7)
~~~

起点已经有 A，不执行 ADD_A。封印使四普通栏变三栏，添加 B 后回到四栏；实际操作仍须逐步通过 FP、等级、封印槽、重复 ID 及底材兼容性检查。

### 3.2 垃圾 T1 在错侧

~~~text
PREP_HAVOC_UNTIL(B所需侧有可封垃圾T1，排除A/B/保护对象)
SEAL_ONCE(按相同侧别/垃圾/T1条件过滤，再取最低原生序)
ADD_B
FINAL_HAVOC_UNTIL(A@ordinaryT7 AND B@ordinaryT7)
~~~

PREP_HAVOC 的局部目标是得到可腾出的 B 侧位置，并非要求已经缺失的 B 先变成 T7。它可以把 A 的 T7 临时挪给其他身份。本候选通过选择器保留 A 身份、不封印／删除 A，但不要求途中 tier≥7 或 roll 不变；最终浩劫再达成 A／B 两个 T7。用户若另外明确硬保护这些属性，按其约束重新判断本路线资格。

入口按所有合格对象检查准备谓词，不能只盯住最初指定的一条垃圾；例如另有合侧 T1 时准备宏应零次退出。真正需要制作时，仍遵循同一固定谓词和原生序选择器。

本候选的保留方式不能被解释为“救赎只洗坏的崇高而自动锁住 A”，也不自动给整个搜索加上身份硬保护。用户未明确要求全程保留 A 身份时，其他候选可以暂时更换 A 后再获得它；具体操作按当时的原生资格判断。用户明确保护时，才排除可能违反保护的分支，不能把某整类操作永久删出所有输入的搜索。

添加 B 可能产生额外升阶、FP 退款及其他已审后处理，最终浩劫从完整结果分布开始。准备耗尽 FP、封印失败、封印成功却无 FP 添加 B等都保留为失败质量。

## 4. x=0：三栏边界不能直接套四栏路线

若已有 A 的短记号为 7710，实际只有三条普通词缀。SEAL→ADD_B 的栏数为 3→2→3，仍不满足浩劫需要四条普通未封印词缀的资格。不能把原空栏当作第四条参与排列。

- B 可直接填入原空栏时，ADD_B→FINAL_HAVOC 是应保留的候选，不强迫先封印。
- B 需要从满侧腾位时，封印／补 B 之外还需一个合法填充步骤 C，使最终浩劫入口确有四栏；C 的实际 ID、侧别、阶数和额外制作副作用都进入模型。
- 填充可以放在合法的不同阶段，须逐步核对资格；本概念规范不预断哪种顺序最优。

这与“两目标都缺的 7710”不同：后者添加 A 先把 3 栏补到 4 栏，然后封印变 3 栏、添加 B 变 4 栏。两者不能只按相同阶数短记号复用路线。

## 5. A／B 都缺：7710 基线

| 侧别 | 固定候选顺序 |
|---|---|
| 直接适合 | ADD_A → SEAL(所需侧垃圾) → ADD_B → FINAL_HAVOC |
| 需要搬位 | ADD_A → PREP_HAVOC(B侧有可封垃圾T1) → SEAL → ADD_B → FINAL_HAVOC |

ADD_A 后的额外加阶可能改变 A 或原垃圾，原垃圾 T1 可能变 T2。直接路线按对象真实阶数封印，不能仍套 T1 参数；准备路线明确要求当前 T1。已有子目标的分支可零次退出准备宏，但各分支执行同一固定谓词，不临时重新搜索路线。

## 6. A／B 全部缺失的 7732 等起点

本节明确指四条实际 ID 均非 A／B 的 7732，而不是仅两条 T7 非目标。没有“先封垃圾 T1”的直接模板，不等于没有可行路线。候选可能涉及救赎搜身份、按实际阶数封印腾位、混沌、浩劫准备及其合法组合；资格取决于实际 ID、侧别、封印容量、保护条件和版本规则。本文不提前给某一组合的概率或最优排序。

| 覆盖状态 | 正确含义 |
|---|---|
| UNASSESSED | 该模式尚未开展系统评价，不是输入验证失败 |
| INCOMPLETE | 已开始搜索但未穷尽已声明范围；可另返回当前已找到的最佳路线 |
| 范围内已证明不可达 | 对公开操作集、宏语言、限制和模型给出不可达证明，仅覆盖该范围 |

前两种不能显示成 IMPOSSIBLE。用户的人脑常见路线只是搜索优先级和验收基线，不是全局可行性白名单；模式识别器不能据此删除 7732 或其他起点。

## 7. 结果与证据归属

本轮已运行[14个四栏输入及1个三栏负例](../../research/common-pattern-cases.json)，包括两种准备模式各自的 x=1…7。所有输入固定手套4:0、角色100级、A=ID4施法速度、B=ID5暴击几率，二者均为前缀：

| 模式 | 初始原生列表顺序 | 固定路线 |
|---|---|---|
| 直接封印 | A4@7、后缀7@7、垃圾前缀2@1、后缀10@x | 封2→补B→最终浩劫 |
| 先搬低阶 | A4@7、垃圾前缀26@7、后缀10@1、后缀7@x | 浩劫至26@1→封26→补B→最终浩劫 |

补词和两类浩劫配希望，封印配绝望。以下为普通FP、`display_parameters_iid`参考模型的完整路线成功率，已包括准备阶段费用、补词暴击／退款及必要封印失败。J是1…63各整数预算等权的成功率均值，不是实际掉落成功率：

| 输入 | J（等权预算） | 假设F=30时成功率 |
|---|---:|---:|
| 直接封印，x=1 | 52.478% | 56.180% |
| 先搬低阶，x=1 | 39.270% | 38.095% |
| 直接封印，x=3 | 50.095% | 53.178% |
| 先搬低阶，x=3 | 27.062% | 23.339% |

两种模式的实际起始装备不同，表中不是同一装备的择优比较。完整[结果](../../research/common-pattern-results.json)包括普通／冰／血、两个独立随机原语参考profile及F=0…63，共90个场景；其中三栏负例的六个场景均为零，表示这条不完整路线无法达到目标，不代表该装备无其他路线。

参考DP的最大成功率数值区间宽度小于1.91×10⁻¹⁴，仅包围其算术误差。浩劫按排除当前布局后的均匀阶数排列计算，有限10000次拒绝保护的参考概率误差另界为 `500×4^(-10000)`。这些固定路线每次正余额动作至少有32%概率实际消耗1点以上，FP不会增加，故期望总动作不超过63/0.32<197；500是保守的跨动作联合界系数。这些界均不包围与真实客户端随机流的全部差异，格点profile也不是原生PRNG位级回放。

独立[逐步采样验证](../../research/common-pattern-monte-carlo.json)覆盖 x=1／3／7、两种路线、三类FP、F=10／30／63，54点各20000条，共108万条完整路线，成功率全部通过预先指定的5σ+1/N交叉核对。采样器不导入路线DP或其转移核。

7732若已含A@T3、B@T2，只有最终浩劫的独立参考曲线在普通FP、希望、F=30时为64.719%，F=63时为86.356%；新回归与既有77tu费用例对齐。若四条ID都不是目标，[7732救赎研究](../research/7732-feasibility.md)则给出另一个实际输入的正质量证据和40万条完整路线采样，不能沿用前者概率。

“四ID全缺”的指定7732手套例，用固定重复救赎＋希望，在普通／血F=63的成功率估计为7.608%（Wilson99%单行区间7.308%–7.919%），冰为10.396%（10.050%–10.753%）。它证明此输入在声明模型内可达；是否值得做以及是否存在更好路线，仍需完整搜索比较，不能用人脑难以计算或材料价格直接否定。

单条路线数值评价完成不等于完成通用搜索，更不等于已证明该模式全局最优。后续研究运行数据必须与游戏客户端／线上频次实测分别命名。
