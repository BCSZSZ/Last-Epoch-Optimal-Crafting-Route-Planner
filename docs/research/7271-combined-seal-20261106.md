# 7271：合并封印停止条件

输入按页面顺序为前缀1=T7、前缀2=T2（已有目标）、后缀1=T7、后缀2=T1；最终要求两条目标前缀均为T7。普通潜能、封印槽空、胸甲、未指定具体词条。固定模型 `le-1.5.3-iid-b46d3015a01bbdb7`。

| 固定路线 | 操作成功率 | 48FP整件完成率 | 成功路径平均FP | 65FP门槛 |
|---|---:|---:|---:|---|
| 浩劫至无关前缀为低阶 → 剥离它 → 补目标 → 浩劫收尾 | 25.00% | 13.83% | 58.83 | 保留，不推荐 |
| 浩劫至前缀1为T1 → 封印 → 补目标 → 浩劫收尾 | 100.00% | 45.44% | 68.21 | 已放弃 |
| 浩劫至前缀1为T2 → 封印 → 补目标 → 浩劫收尾 | 69.00% | 32.13% | 66.43 | 已放弃 |
| **浩劫至前缀1为T1或T2 → 封印 → 补目标 → 浩劫收尾** | **84.50%** | **50.55%** | **55.68** | **保留，当前方案** |

浩劫只重排阶数，词缀身份和顺序不移动。图中前缀2已是目标；若按字面封印前缀2，它不能再满足普通槽目标，也不能把同一ID重新加回普通栏。因此有效路线应封印无关的**前缀1**。

## 原因与修正

旧模板只枚举“等待某个单一阶数”，遗漏了“首次遇到一个允许阶数集合即停止”。两个单阶路线分别超出65FP；遇到T1或T2就停，可减少等待费用，使成功路径均值降至55.68。问题发生在固定模板生成，原子概率规则和FP评价本身没有算错。

本例首次出口T1、T2各占一半；四条普通词缀、两条T7时，封T1为100%，封T2为69%，因此操作成功率为 `(1+0.69)/2=84.5%`。FP均值和48FP完成率由联合状态／费用分布完整评价，不能用上述平均概率或FP均值直接换算。

模板增加允许T1至T2、T1至T3、T1至T4的固定封印窗口，保留单阶模板，优先让T1至T2窗口进入早期候选。不是临场重新优化，也不是已证明覆盖任意停止集合的全局最优搜索。

界面根据原始词缀身份标注前缀1等槽位；在身份及阶数支持仍可确定时，把通用筛选范围与实际支持相交。本例原有低阶只有T1、T2，显示“浩劫至前缀1为T1或T2”，不再显示T1–T6。救赎等改变身份后不继续沿用原槽位身份事实。

## T7数量约束

普通制作不能生成新的T7，简易目标前后缀合计不得超过起始**普通槽**的T7数，封印不计入。浩劫可以跨前后缀重新分配已有阶数，因此不按起始各侧的T7数分别限制。按钮禁用超额新增；降低起始T7后保留原目标，允许向下调整，计算入口拒绝尚未修正的矛盾输入。
