# 产品需求：固定装备打造路线规划器

状态：Phase 0 研究与数学架构审阅稿。日期：2026-11-03，日本时间。

## 产品目标

面向《最后纪元》玩家，为一件给定装备计算起点至目标的一条主推荐路线。起点与目标可精确指定词缀、最低阶数、可接受替代项、封印要求、保护要求和可选 roll 限制。起始装备的 FP 类型必须明确；实际剩余 FP 不作为必填输入。结果展示一组假设初始 FP 下的成功率及消耗，不要求玩家回填每次游戏制作结果。

输入不是自然掉落模型。不会把某个假设 FP 区间解释为这件装备的实际剩余 FP，也不优化购买替换底材的无限重复生产。

## 本轮已确定的产品政策

1. 所有操作先完整执行原生转移和费用／材料后处理，再判断产品停止条件。
2. 剥离未命中宏预先声明的允许删除集合，即判该路线失败；保留该笔已发生的真实装备变化与消耗，不执行后续宏。
3. 必要封印的一次检定未成功，即判路线失败；不追加封印重试或补救。失败后的原生加阶、可能暴击与退款仍计入该失败叶。
4. 浩劫和救赎等重复行为聚合为宏动作；宏内提前声明继续、成功和失败条件。
5. 主路线的宏顺序、目标选择及支持材料选择在计算前固定。仅允许预先定义的跳过、成功停手和失败退出，不根据途中结果另行搜索路线。
6. 首版动作集合包括添加／升级、希望、绝望、浩劫、救赎、混沌、剥离；三种 FP 分别建模。精炼、塑形、进化等保留扩展位置，不把未实现动作计入搜索覆盖。

## 输入与结果

输入包含完整装备状态、角色制作等级、目标、可选保护／操作限制，以及可选实际库存和使用预算。实际库存与“最多愿意使用几枚”的预算不是同一个概念：本地代码显示库存可影响暴击资格，见[打造审计](research/forge-fp-audit.md)。默认不限制库存是明确的产品建模约定。

结果包含主推荐宏序列、各宏停止条件、尝试次数、FP 消耗分布、成功率曲线、实际材料消耗与产出、评分约定、模型版本、计算精度和搜索完成状态。无法达成的目标与搜索未完成必须分别说明。零成功概率时成功条件指标不适用。

## 技术与交付

React、TypeScript、Vite 为首选。规则、宏与搜索为独立模块，浏览器 Worker 承载计算，界面只调用统一异步规划接口。首选 GitHub Pages；如私有仓库不具备 Pages 资格，用户已授权当前仓库改为公开。数学架构确需 Python 且资源测试通过时评估 Streamlit，再使用自有 AWS。

本轮交付研究快照、证据、复现脚本和规范规定的 11 份文档。生产求解器、网页与部署在本阶段审阅后实施。研究脚本不是已完成的产品引擎。

## 验收

概率来自版本化原生／资源证据；限制不自动放宽；失败立即终止政策有独立测试；同输入和模型可复现；概率评价精度与最优性证明分开；界面无需实际剩余 FP 或逐步回填。详细矩阵见[验证计划](validation-plan.md)。
