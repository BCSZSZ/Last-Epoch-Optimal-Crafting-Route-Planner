# 状态、目标与异步规划接口

## 模块外部接口

界面只使用异步规划接口 `plan(request, {signal, onProgress}) -> Promise<PlanReport>`。浏览器 Adapter 将主线程的回调和取消信号转换为 Worker 数据消息；函数和 AbortSignal 不直接通过 Worker 传递。未来 Node.js Adapter 使用同一请求／报告契约，生产核心不依赖 React、DOM、网络或存储。

`PlanRequest` 包含 `modelId`、`item`、`craftingContext`、`target`、`constraints` 和 `scoring`。`item` 不含必填的实际剩余 FP。内部 `EvaluationState` 才加入 `hypotheticalFP`、宏阶段、实际库存余额和使用预算余额。请求的模型修订锁定整个计算，不能中途切换数据库。

## 装备状态

- 底材用 `(baseTypeId, subTypeId)` 标识，不能仅用本地化名称；同时保留物品类别、稀有度、实际物品等级、需求与职业限制。
- 每条词缀保留原生列表顺序、稳定 ID、显示阶数与原生存储阶数的明确转换、roll 原始字节／分量及特殊类别。不可按 ID 排序后丢掉顺序。
- 前后缀、普通封印、先古 T8 封印、腐化槽分别表达；实验、冠军等特殊类别不靠名称判断。目标指定匹配的槽角色，不能把封印 T7 混为普通栏 T7。
- FP 类型为普通／血／冰，映射以原生枚举及序列化审计为准。持久化普通装备 FP 为 0–63，见[打造审计](research/forge-fp-audit.md)；这不是掉落分布。
- 记录腐化、不可制作等会影响动作资格的原生标志。数据库中存在的底材或词缀不自动等于该动作可使用。

`craftingContext.playerLevel` 是必要的制作上下文：普通加阶资格与额外暴击升阶实际读取角色等级，不默认 100。研究期间先完整确定代码依赖；不在本阶段扩展隐藏信息的输入／展示方案。

## 库存与限制

实际 `inventory` 表示材料在仓储／制作槽等必要位置的数量，影响原生 CheckForShard、消耗及退款。`usageLimits` 表示用户自设“最多消耗／尝试”的上限，不改变原生资格。二者分别建模，不能把设定预算 1 当成玩家只有最后一枚碎片。

默认 `inventory=unbounded`，公开说明它是建模假设。有限库存执行完整扣减、移动到制作槽、返还和再次检查顺序。支持材料是否消耗也由原生结果决定。取负库存、未知材料或未知 ID 报错。

`usageLimits.maxAttempts` 按开始一次完整制作记账，退款不倒扣次数。`maxConsumed` 是实际消耗的硬上限：动作开始前须确保所有正概率完整结算分支均不会越限，否则不开始动作并以资源限制退出。不得先超支再把该分支写成“及时停止”。

## 目标与保护

目标支持所需 ID、最低阶数、可接受 ID 集合、普通／封印槽要求、可选 roll 限制及不受约束的空余项目。“可选”不应生成必须满足的成功谓词。完全相同 ID 不应被多个互斥要求重复占用。

固定位置解释为稳定词缀／槽角色，不把 UI 当前排序当作游戏可操控位置。保护要求显式记录要保护的身份、阶数下界或 roll 属性；能够违反硬保护的动作不能作为合法候选。规则内未找到路径与全游戏不可能的结论分开。

先检查语法与数据库资格，再检查前后缀容量、封印容量、等级与操作集可达性。T7/T8 目标不能被普通升级凭空满足；未覆盖的精炼或进化目标应报告操作覆盖范围。

## 核心内部接口

原子转移输入完整 `EvaluationState`、固定动作及不可变机制快照，返回联合原子结果：概率、下一个完整状态、尝试／材料记账、FP 变化、该笔原生结果标志。不要将“状态变化”和“平均扣费”独立返回后相乘。

宏与路线评价消费该联合分布。报告不回传整个搜索状态树，只返回推荐、曲线、分布摘要、证据与计算状态。进度包含任务 ID；取消或新请求到来后旧任务不能覆盖新报告。同步重计算中使用协作式让出执行权，或由 Adapter 终止 Worker 并重新初始化，不能仅发送无法被处理的取消消息。

## 精度与搜索状态

`evaluationStatus` 描述按哪个随机原语模型精确求解、近似及误差；`searchStatus` 描述候选语言是否穷尽；`optimality` 描述证明范围。三个概念不得互相代替。方法地址登记也不等于其全部行为已验证。
