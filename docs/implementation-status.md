## 已落实的机制修订

- 旧兼容回退只有501／502／503／504，且仅对已有词缀生效；505不在表中。详见[原生调查](research/legacy-forge-compatibility.md)。
- 碎片存在性不是“库存无限”：实验词缀没有普通碎片，不能直接成为添加／升级／绝望的主碎片目标；已有实验槽仍按原生执行层参与浩劫和额外升阶。
- 等级只按原生tier贡献和底材需求计算；封印及非Standard槽不贡献当前等级，AfterShard的查找closure另有限制。详见[等级和雕文调查](research/crafting-level-requirements.md)。
- Order保留普通主升级与暴击专门主分支的roll；暴击fallback路径仍重抽roll。必要封印失败保留升级／暴击／退款，再吸收失败。
- 原子分布及常见路线返回声明模型下的算术区间；游戏随机流与模型的差异没有被误包装成该区间。

## 复现和版本

`python -X utf8 scripts/build_runtime_model.py --verify-only`校验运行投影，`npm run check`与`npm test`核对TypeScript。生成模型绑定完整源快照、研究证据及核心实现哈希；模型不匹配拒绝计算。核心没有React、DOM、Worker、网络或存储依赖。

当前不使用完整的状态改变救赎宏精确核；该路径明确请求后续直接采样，绝不套起始命中率几何分布。完整搜索和网页尚未交付，不把研究脚本或常见路线评价当作已完成的自动规划产品。

当前检查点已通过42项TypeScript回归、30项Python完整性回归及全量研究验证；新增等级研究34例也通过。测试直接调用产品规则／宏接口，救赎一发结果与独立Fraction证据一致，7710三类FP及已有A的14个771x输入与独立Python路线结果对齐。

首次[Node基准记录](../research/phase2-node-benchmark.json)覆盖双T7浩劫、7710、7713准备、剥离补栏三类FP的完整曲线，以及稀有救赎单次原子动作。单条已支持路线的评价计算段最大约215.3毫秒；子进程峰值RSS最高约123MiB，含Node运行时。硬件为i5-13600KF／32GB，模块加载和进程启动不计入计时。救赎项不是完整重复路线；这些数据不证明浏览器、低性能设备或完整搜索性能。
