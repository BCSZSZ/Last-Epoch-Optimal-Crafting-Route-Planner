# 初始 FP 生成与 63 上限复核

2026-11-03，日本时间。只读核对当前安装 **1.5.3／Steam build 26087601**；未运行客户端制作或采集线上掉落。

## 结论

**63 是当前可持久化普通装备的 FP 硬上限，不是自然掉落 FP 的均值，也不是 1–63 等概率掉落。**在生成等级 100、普通式生成上下文、抽 FP 时已经有 T6／T7、raw rarity≥3 的常规入口，初始 FP 的显示参数 iid 模型为：

\[
F_0\sim0.89\,U_\mathbb{Z}[32,48]+0.11\,U_\mathbb{Z}[32,56],\qquad E[F_0]=40.44.
\]

这是特定入口的精确模型推导，不是所有来源双 T7 装备的无条件掉落平均。[原生方法与 PMF](../../research/fp-generation-20261103.json)

| 初始 FP | 概率或分位 |
|---|---:|
| 32–48，每个整数 | 5.6752941176% |
| 49–56，每个整数 | 0.44% |
| 平均 | 40.44 |
| P10／P25／P50／P75 | 33／36／40／45 |
| P90／P95／P99 | 47／48／54 |
| 大于 48 | 3.52% |
| 至少 50 | 3.08% |
| 至少 55 | 0.88% |

因此可以把 **40 FP** 作为高等级普通掉落崇高装备的一个有依据的参考预算，并以 **32／48 FP** 做预算敏感性比较。不能把 63 当作典型起点，更不能根据平均初始预算40.44直接宣称“期望消费高于40.44的路线不可能成功”。消费具有长尾和零费用，最后一次制作还允许超出剩余余额结算。

## 原始抽样公式

设生成等级为非负整数 `L`，`t=floor(L/10)`。汇编中的有符号常数乘法是整数除法向零取整；本报告域内等价于 floor。

先根据当前 raw rarity `r` 与传入的不可打造词缀布尔值 `h` 选 `a,b`：

| 条件 | a | b |
|---|---:|---:|
| h=false，r=0 | 24 | 32 |
| h=false，r=1 或 2 | 22 | 28 |
| h=false，r≥3 | 24+t | 34+t |
| h=true，r<3 | 35+t | 40+t |
| h=true，r≥3 | 38+t | 46+t |

对 `Normal／SoulGambler／Nemesis／RageOfMorditas` 这四个普通式上下文：

```text
lo = 2 * floor(a / 3)
若 Roll(float32(0.11)) 成功：NextInt(lo, b + 1)
否则：                         NextInt(lo, a + 1)
```

`NextInt` 上界排除，故显示支持集含 `a`／`b`。注意下界是 `2*floor(a/3)`，并非总能写成 `floor(2*a/3)`。例如 L90、h=true、r≥3 时 a47，真实下界30；误写另一式会得到31。

商店、赌装另走：

```text
Shop:    NextInt(floor(a/2), (2*floor(a/3)) | 1)
Gambler: NextInt(3*floor(a/5), (4*floor(a/5)) | 1)
```

其中 `| 1` 是按位或，不应无条件理解为“加一”；两个参数仍是下界含、上界不含。L100、h=true、r≥3 的这两个条件分支分别是24–32、27–36。这不是该游戏来源一定能以该 h/r 生成的证明，更不是血／冰 FP 的分布。

| 条件入口 | 初始支持集 | 均值 |
|---|---:|---:|
| L100、h=true、r≥3 | 32–56 | 40.44 |
| L90、h=true、r≥3 | 30–55 | 38.94 |
| L85、h=true、r≥3 | 30–54 | 38.44 |
| L100、h=false、r≥3 | 22–44 | 28.55 |
| h=false、r1/2 | 14–28 | 18.33 |
| h=false、r0 | 16–32 | 20.44 |
| L100、h=true、r1/2 | 30–50 | 37.775 |

抽 FP 的方法没有读取具体词缀权重、具体底材、总 T 阶、T7 条数、地图腐化或阵营等级。底材所属类型先决定能否具有 FP；等级、raw rarity、h与来源上下文决定该原始抽样。阵营／镜片等仍可在外部改变输入与后续状态，不能据此断言任何来源都不受它们影响。

## 7272、7710、7732 能否共用

常规 `GenerateAffixes 0x11c0d40` 的顺序：

1. `RollAffixes 0x11c66a0` 完成身份、阶数及其内部强制崇高处理，并输出 `hasUncraftableAffix`。
2. 更新 raw rarity 时仅按生成的普通词缀数下调需要下调的范围。
3. `0x11c15fb` 读取该布尔，`0x11c1604` 传来源上下文，`0x11c1612` 调 `rollForgingPotential`。
4. `0x11c1624` 调 `SetForgingPotential`。

`RollAffixes` 在观察到 stored tier≥5（显示T6及以上）时设置 h（例如 `0x11c728f–0x11c7295`）；其强制崇高路径亦在返回前设置 h（`0x11c7355`）。因此**该函数内部的 forceExalted 在抽 FP 之前，属于高预算分支**，不能把它一概列作“先抽低FP、后变崇高”。

对于未被后续来源改写、生成等级100、raw rarity≥3的常规三／四普通词缀双T7输入，7272、7710、7732的 h均为true，共用上面的40.44分布。第二条T7不会额外增加初始FP；低阶是T1、T2还是T3也不会继续加分。JSON逐项保存了这三个结构、三种FP类型在**同一个原始roll入口**的 PMF 引用。

以下不能由现有输入唯一确定：

- 已经制作过的当前剩余FP；原始分布不等于当前余额分布。
- 同样最终呈现双T7，但通过抽FP之后的实验插入、镜片处理、赋能或其他来源后处理取得的装备。
- 由冰相似物品、血仪式、复仇武装产生的最终装备；其源状态和后处理有FP改写。
- 跨所有获取来源的总体平均；需要每种来源／等级／种子／仪式深度及玩家挑选条件的真实混合权重。现有项目没有这份掉落频率调查，不能用“各来源等权”伪装成实际全体平均。

## 冰／血及赋能边界

**FP类型不直接改变 `rollForgingPotential` 的原始PMF；取得该类型的来源会改变最终PMF。**

血来源的 `GenerateItemForRageOfMorditas 0x11c1f70` 在 `0x11c27d9／0x11c291c` 以 GenerationContext5 调通用生成（包含FP），之后 `0x11c2a34／0x11c2a42` 才将符合条件的物品 FP 类型设为Ice2／Blood1。这些类型写入没有重新抽FP。随后可有仪式共同赋能，所以最终领取的血装不能直接套原始40.44。

冰使用 `SimilarItemExtensions.GetSimilarItem 0x1240e80`。已重新核完整12442字节及哈希：

- `0x12428d7–0x1242942` 在中间结果状态上，以当前是否崇高作为 h、context0重新抽一个候选FP。
- `0x124295b` 开始比较该候选与源FP，并有70%选择、源FP低于50时的调整、`(源FP/60)^2` 检定和区间再抽；`0x1242ae0` 写入。
- 某些删词分支又在 `0x1242d9b` 抽候选，`0x1242db6` 后只在比当前FP更大时改写。
- 这些操作在源封印回流、多崇高重抽和最终保底之前，因此最终双T7条件亦会改变筛选后的分布。

故冰领取的最终 FP 依赖源FP、词缀身份／阶数／数量、封印及仪式参数，不能仅按“ICE”给唯一掉落均值。

共同赋能 `EmpowerMagicRareOrExaltedCore 0x11fdcc0` 在 `0x11fe801–0x11fe815` 使用 `min(63,57+bonusMaxForgingPotential)` 为目标界限，在实际当前FP与封印结果等条件下决定是否补FP。`RollForgingPotentialToAdd 0x1231df0` 根据到目标界限的距离选最低增量1／2／5及相应上界；随后有重复抽增量选择和 `0x11fe8de–0x11fe90f` 的最终0–63钳制。这是新的状态相关补充，不能当成重新U[1,63]或“所有血冰装备固定63”。

## 63、费用均值和放弃阈值的不同含义

以下三件事必须同时保留：

1. setter、重建序列化和反序列化证明当前物品可持久化FP是0–63；普通L100原始生成的上述高预算入口最高56。
2. 路线报告当前 `E[C|成功]` 假设FP持续充足，它可以高于63；它是比较路线随机消费难度的量，不代表一件物品能拥有82或100FP。
3. 费用不是必须全部由原始余额支付。余额尚为正即可执行最后一次制作，完成后再归零；希望／冰、暴击退款和低FP保留亦会影响预算内的成功率。不能简单以 `P(C≤F0)` 代替真实结算，更不能只用 `E[C|成功]` 与 `E[F0]` 的比较给出概率。

因此 **100FP门槛确实非常宽**：相当于典型40.44初始预算的2.47倍。82.68FP也约是2.04倍；即使其“无限预算操作成功率”高，也不能称实际完成率70%。合理的下一步是同时显示或研究在参考预算32／40／48和/或上述真实初始PMF下的预算内成功率，再由产品选定剪枝门槛。

把门槛降到约40／50／60，分别是偏严格／折中／较宽松的产品偏好，**本次原生审计本身无法证明其中一个是数学上的正确阈值**。新门槛若用于截断搜索，还须保证是完整路线的上/下界证明；成功条件均值在加入后续成功筛选后可能下降，不能把任意前缀条件均值超过阈值当作普遍安全剪枝。
