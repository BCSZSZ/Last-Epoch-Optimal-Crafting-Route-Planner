# 首阶段审阅结论

日期：2026-11-03，日本时间。当前审阅包以本机 **1.5.3 / Steam build 26087601** 为证据基线，完整保留[原始启动规范](../BOOTSTRAP.md)。本轮没有客户端制作频次或线上服务器实测。

## 已完成

11 份研究与架构文档、当前游戏版本化快照、两份原生审计、统一证据矩阵、独立研究环境和复现脚本已交付。生产模型清单为[model-snapshot.json](../research/model-snapshot.json)，明确标注 `PHASE_0_REVIEW`、`productionReady=false`。

数据库包含1156个词缀、42类资源类型及923个底材定义；包括旧版／不可掉落条目，不能把完整资源数量当当前可制作名单。方法登记、实际行为审计及数学样例验证各自单列，不用登记总数夸大审计范围。

## 对后续引擎最重要的发现

1. **FP评价域可定为1–63。** 当前setter、初始生成、赋能和六位持久化共同支持0–63边界；元数据中的255不是可直接采用的普通装备FP上限。等权域仍是产品选择，不是掉落分布。
2. **费用有低FP后处理。** 除希望、冰与暴击，还存在有顺序的保留2／保留1检定。忽略它会改变预算内成品率。
3. **当前混沌不走暴击入口。** 普通／血暴击还取决于操作、是否成功封印，以及仓储中是否仍有主碎片。用户最新指定所有材料无限，当前模型将仓储检查按有货求值，移除库存输入及材料代价。
4. **暴击同时改变装备、FP和材料。** 额外加阶不是简单均分给另一词缀；角色等级、primary偏置、退款和支持保留必须放进联合核。
5. **成功／失败绝望的基础费用阶数入参相同。** 最终消耗可因失败后暴击等后处理不同，不能归因于两份不同的基础收费阶数。
6. **救赎是逐槽相关抽样。** 已有目标的位置和先后顺序会改变后续候选；不能独立相乘或排序丢掉原生顺序。

完整原生定位及当前字节哈希见[FP审计](research/forge-fp-audit.md)、[词缀动作审计](research/affix-actions-audit.md)与[证据矩阵](../research/evidence-matrix.json)。这些发现修正新模型，不覆盖父项目历史研究或课件。

## 已执行的计算检查

- 合成数学例仅验证通用计算：7例、124项精确有理数检查，覆盖零费用状态变化闭环、非终止、失败吸收及成功条件混合均值。
- 当前资源手套例：三种救赎起点分别精确枚举289终态，各执行20万次独立直接抽样交叉核对；参考模型标签与原生格点精度分开。
- 非暴击符文费用：1536组精确单位概率质量检查和9项手算断言，覆盖三类FP、希望及低FP保留。
- 版本／文件变更拒绝、完整快照、方法引用、文档本地链接及BOOTSTRAP原始哈希，由研究验证与独立负例测试检查。

执行记录及模型范围见[validation.json](../research/validation.json)。这些不是完整产品搜索或客户端制作验证。

## 架构和部署结论

保留React＋TypeScript＋Vite。界面只调用异步规划接口，Worker管理执行；规则、宏与搜索不依赖界面，必要时同一套代码可迁Node服务端。浏览器性能首次检查提前到Phase2，完整求解器Phase5重测。

GitHub Pages优先；私有仓库无资格时已获授权将当前仓库公开。只有确需Python生产数值生态且资源实测合适时转Streamlit，再使用AWS。本阶段尚无需要发布的生产应用，不提前把研究网页冒充成品。

## 审阅重点与下一步

审阅[优化目标](optimization-objective.md)、[概率模型](probability-model.md)和[未决事项](open-questions.md)：默认1–63等权、独立随机原语假设及固定宏语言最多12阶段的初始搜索预算。材料固定无限且不参与排序；新增[7710完整准备路线验例](examples/7710-to-target-double-t7.md)验证正常补词、准备浩劫与最终浩劫的组合。

现有不兼容词缀例外表、加权随机位级边界、多属性roll显示投影仍明确为部分验证。它们应在相应生产功能实现前补齐；线上一致性另列验证。本轮按已批准计划停在规则与数学架构审阅点，审阅后进入Phase1。
