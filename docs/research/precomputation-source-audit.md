# 预计算的复用条件与当前求解器重复工作审计

2026-11-03。对象为提交`ebcce3c`、模型`le-1.5.3-iid-b88b0a4321c1f217`。本笔记依据本地项目源码与已提交实验记录，只作分析，不修改生产求解器，也不声称测得任何新版预计算加速比。

## 结论

值得预计算，最有价值的对象是可复用制作阶段的完整退出核、退出费用首矩、可证失败／费用下界以及有限模板的评价结果。常见默认结构可以逐步做到“资格检查＋查表＋少量组合比较”；不能只给23个上层标签各存一个最优答案，也不应先枚举全部具体装备ID组合。当前23节点是模板路由，实际数值仍按完整装备与固定程序位置区分。[分层实现](../../src/core/hierarchy.ts#L79)、[数值状态键](../../src/core/intrinsic.ts#L71)

## 目前仍在重复计算的部分

1. `plan`每次新建`RuleEngine`、编译模板并新建`IntrinsicWorkspace`。原子核和完整路线结果缓存仅在这次请求内共享；再次规划不会自动复用上一请求已完成的计算。[planner.ts:255–268](../../src/core/planner.ts#L255)、[intrinsic.ts:38–54](../../src/core/intrinsic.ts#L38)
2. 每个`calculate`仍重新构造程序图、做可达性分析及吸收核验证；前缀剪枝还会分别调用多个前缀的`calculate`。[intrinsic.ts:71–128](../../src/core/intrinsic.ts#L71)、[calculate](../../src/core/intrinsic.ts#L231)、[前缀评价](../../src/core/intrinsic.ts#L295)
3. 同一个完整图先求成功概率，再为每个外层阶段单独解一个费用奖励右端项；保留路线还另外构造全终止系统并求总费用。系数关系与图结构可复用，当前实现尚未缓存矩阵分解或宏退出核。[intrinsic.ts:244–290](../../src/core/intrinsic.ts#L244)
4. 浩劫已经把无限重试压成有限退出核，但每次仍按当前装备枚举布局、检查目标、计算退出费用。[intrinsic.ts:106–117](../../src/core/intrinsic.ts#L106)

该提交的Node普通潜能例中：7713准备路线整次约7.032秒，选中路线33状态、共评价24模板、5模板未完成；7732缺两目标约2.987秒，选中路线1737状态、共评价48模板、2模板未完成。这说明耗时还包括竞争模板和未完成候选，不能把“主路线已查表”直接等同于“整次搜索已消失”。这是旧提交测量，不是对各内部函数耗时的归因。[原提交性能记录](https://github.com/BCSZSZ/Last-Epoch-Optimal-Crafting-Route-Planner/blob/ebcce3ce628a3f0b4345519d8e7a9a011ca3fab3/research/hierarchy-runtime-benchmark.json)

## 可预计算对象与最小复用条件

| 对象 | 可以保存什么 | 必须保留或检查的条件 |
|---|---|---|
| 原始抽选池 | 普通前后缀候选ID、有效制作权重、分组计数与池签名 | 模型／资源版本、装备类型和职业资格；各底材实际池一致才可共享 |
| 费用规律 | 各费用上界、希望开关、FP类型的费用均值／分布 | 当前主指标无余额截断；有余额模型不能套这个缩放 |
| 绝望与剥离 | 封印分支、NG；合法移除池的均匀分支 | 普通数量、tier、崇高标志、原生动作资格、接受集合；全程保护先检查 |
| 添加／升级 | 暴击、额外加阶和退款的联合结构核 | 主对象角色、当前tier布局、额外升阶候选、等级通过情况、支持雕文；不能只缓存平均费用 |
| 最终浩劫 | 合法入口到成功的完整均值／概率 | 目标身份已齐、真实普通布局、目标要求、动作保护、次数上限；无roll限制时可大幅压缩 |
| 准备浩劫 | 每种允许退出布局的概率与费用首矩 | 同一子目标、目标／垃圾位置、tier多重集、资格与原生对象选择语义 |
| 救赎阶段 | 动态抽选链的完整退出分布、退出次数／费用首矩、可证下界 | 实际池签名、固定排除ID／权重计数、被重抽槽的原生顺序／tier、目标角色及停止谓词 |
| 混沌窗口 | 窗口成功／耗尽出口的联合核 | 当前ID排除集、升级窗口tier、侧别、原生选择顺序、是否浩劫恢复、耗尽后的固定后缀 |
| 整条固定模板 | P(S)、E[C·1S]、完整状态／数值版本、覆盖范围 | 精确相同或经证明等价的入口、目标、约束、宏语法及动作参数；未完成结果不能升级为最优证明 |

抽选池会排除装备上的全部ID，且每个槽重抽完成后更新装备，下一槽读取更新后的池；仅用初始A／B权重或“平均词条权重”不足以给完整救赎宏建表。[catalog.ts:88–109](../../src/core/catalog.ts#L88)、[rules.ts:283–301](../../src/core/rules.ts#L283)

普通添加／升级的额外加阶先选择对象，再检查角色等级；不通过也不另选。等级与特殊类别属于结构核的资格上下文。等级计算基于底材最低要求和普通Standard词缀的阶数贡献，并非只靠上层类别判定。[额外加阶](../../src/core/rules.ts#L308)、[等级公式](../../src/core/levels.ts#L5)

## 两个很小且可明确证明的复用空间

当前费用上界只有`10/12/14/18/20/24/25`七种；希望开关两种、FP类型三种，费用规律最多42种组合，秩序／无希望在纯费用规律上可以共用，但状态后处理不能因此合并。[费用选择](../../src/core/rules.ts#L236)、[费用核](../../src/core/probability.ts#L81)

最终浩劫的主场景是两个T7、两个T1…T6。低阶多重集仅有`C(7,2)=21`种；带位置的tier布局有`C(4,2)×6²=216`种。目标已合法存在、无roll或硬保护冲突、没有次数上限时，低阶相同／不同时成功命中率分别为1/5、2/11，平均5或5.5次。这一收尾完全没有必要每次重新建立完整路线图；但它本来已经很小，不应把它的节省估计成全部搜索的节省。[浩劫退出核](../../src/core/intrinsic.ts#L106)、[实际同标签反例](../../research/upper-state-havoc-check.json)

## 普通与冰潜能可共享状态图，费用按0.7缩放

在当前持续FP模型下，ICE不改变词缀状态分支。状态分支只针对BLOOD改变普通暴击率；ICE仅在费用自由分支中引入额外30%免扣，因此每个出口的费用首矩相对NORMAL乘0.7，概率核不变。只要宏／目标／保护／显式次数限制相同且不读取FP余额，整条固定路线P(S)相同，成功路径FP均值及所有费用首矩均乘0.7。BLOOD对添加／升级／封印失败后处理另有状态影响，不能整条路线盲目共图；纯无普通暴击的符文阶段可以再单独证明共享。[状态暴击分支](../../src/core/rules.ts#L212)、[费用联合投影](../../src/core/rules.ts#L168)、[ICE费用参数](../../src/core/probability.ts#L81)

必须缓存原始完整结果或费用核，不能把NORMAL“超过100已放弃”的状态直接搬到ICE：例如完整普通费用130对应冰91，而普通计算若只证明下界103便停止，该下界乘0.7仍不足以判断冰是否过门槛。阈值判定应在查表／缩放之后独立进行。[判定与部分费用含义](../../src/core/intrinsic.ts#L29)、[费用下界提前退出](../../src/core/intrinsic.ts#L231)

## 宏接口必须保存出口，而不只是两个平均数

设阶段从i退出到j的概率为K(i,j)，费用联合首矩为R(i,j)=E[C阶段·1出口j]。对固定后缀的成功概率p(j)和成功费用首矩m(j)，组合为：

```text
p(i) = Σj K(i,j) p(j)
m(i) = Σj [K(i,j)m(j) + R(i,j)p(j)]
最终成功路径平均FP = m(i)/p(i)
```

后续封印／剥离NG会选择性留下不同出口，因此阶段的单个平均FP不够。当前生产原子接口已经返回每个出口的概率和费用首矩，预计算可以沿用这个语义，不必维护第二套规则。[DemandDistribution](../../src/core/rules.ts#L168)、[条件成功奖励计算](../../src/core/intrinsic.ts#L257)

可以预计算或缓存同一内部转移Q的分解／求解信息，再同时应用到多个固定后缀右端项；这不等于按随机出口重新选最优后缀。每条固定模板仍必须按规划前确定的分支解释。[固定分支编译](../../src/core/intrinsic.ts#L57)、[求解器](../../src/core/intrinsic.ts#L174)

## 不能无条件合并的字段

救赎已有独立研究将手套的342个原生有序ID状态压成33个权重／目标角色状态，并核对转移最大差约1.78×10⁻¹⁵。这证明特定纯救赎链能共享权重类结果，不证明任何后缀都能把相同权重垃圾随意换成一个代表ID。[压缩脚本](../../scripts/research_redemption_intrinsic.py#L39)、[独立核对记录](../../research/redemption-intrinsic.json)

例如填充明确使用按ID排序的候选表，且取当前第一个合法ID；封印／混沌选择器检查原生实际资格；救赎保留原生逐槽更新。因此一般复用键必须保留这些行为或加入等价证明，不能只保留同侧／同权重。[填充顺序](../../src/core/hierarchy.ts#L87)、[运行时选择器](../../src/core/evaluation.ts#L71)、[实际填充](../../src/core/evaluation.ts#L81)

预计算键至少分为两层：

- 规则／阶段层：模型数据与规则版本、池签名、固定排除及槽位／tier／目标角色、停止条件、资格／等级行为、roll／保护、支持物、显式操作次数限制。
- 完整推荐层：还要包含模板语法版本、允许动作、最大宏阶段、目标／约束及已穷尽的候选范围。资源预算不是机制参数；其导致的未完成标记不能作为不可行结论永久缓存。

所有完整原始ID查询当然可以直接存结果，但具体ID／tier／顺序／目标／额外槽／等级／保护的交叉积会很大；应先找经证明的阶段等价类，再计算表的真实规模。早期8580个抽象代表是结构覆盖人口，不是已经证明的8580个通用数值键。[既有结构覆盖限定](../../research/strategy-classification-coverage.json)、[当前完整装备键](../../src/core/catalog.ts#L120)

## 建议优先顺序

1. 先为最终浩劫、费用和普通加阶结构核建立小表／闭式结果，并加入纯函数形式的宏退出核缓存。这些最容易给出完整复用条件。
2. 对当前最贵的救赎／混沌阶段做一次确定性剖析；从同一内部图的重复求解、同一前缀／后缀及相同阶段核开始复用。不能仅依据选中路线状态数推测全部耗时归属。
3. 离线预计算常见池签名下的动态重抽核和有证负面结论；只存平均值不够。先覆盖默认等级、Standard、无roll／硬保护的常用范围，再扩展额外槽和特殊输入。
4. 在限定范围内把全部已声明模板算完，保存Pareto候选及范围内最优证明。完整命中这种表时，在线可只验证条件、实例化路线和比较；未命中仍由当前求解器补算。
5. 静态分片、版本校验和浏览器持久缓存可以保留GitHub Pages架构；避免把一整份巨大世界状态表强制送入每次首屏。精确存储／下载规模及实际加速比须在生成表和浏览器测试后再报告。

最终可实现的是“常见范围近似零在线数值求解，特殊范围少量补算”。这是实现方向与可行性判断；当前代码尚未实现这些离线表，不把研究数据或预算未完成的主推荐直接标成已证明最优。
