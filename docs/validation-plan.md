# 验证计划与证据边界

## 已执行的首阶段检查

本阶段检查安装指纹、数据库完整性、方法字节、提取确定性、研究计算样例和文档／证据链接。最终结果由 [validation.json](../research/validation.json) 记录；不能把这些检查写成生产引擎、浏览器产品或游戏客户端实测通过。

本地重复提取与 `--verify-only` 应逐字节一致。清单内每份数据的 SHA-256 和长度必须正确。跨平台重建不含当前机器绝对路径或临时执行时间，审计日期是固定版本元数据。

## 原子规则矩阵

- 资格：前后缀容量、已有 ID、普通／实验／冠军等类别、各封印槽、底材／职业／等级限制与已腐化状态。
- 浩劫：四普通栏、重复阶数、所有阶数相同、排除当前布局、拒绝抽样保护及 roll。
- 救赎：全部合法崇高逐槽重抽，前槽结果更新后槽候选；不同原生顺序不能被状态规范化合并。
- 混沌：目标按实际制作权重选择，失败身份改变下一次候选；当前版本暴击资格按 Forge 审计，不能套旧研究。
- 封印：成功移槽与失败加阶；必要封印失败后完整结算但后续宏次数为零。
- 剥离：从合法候选均匀选择的数学原语、命中允许集合与失手叶；返还材料单独记账。
- 暴击：主制作槽选择偏置、角色等级、无限物料下仓储资格成立、免 FP、主材料返还与支持保留。
- FP：0、1、2、3、63；费用大于余额、最后一笔成功、希望／冰保留、血追加检定、低 FP 有序保留、退款。

## 宏、路线与搜索

精确手算小模型与完整枚举为基线；概率质量与终止／失败／成功分布一致。零成本闭环必须求解，不用均值除 FP；不吸收闭环应报告不终止概率和无限期望。

一次宏目标已满足的跳过、运行中成功、必要封印／剥离政策失败与FP耗尽分别覆盖。所有材料固定无限，不设库存／价格／材料用量上限测试。完整原生后处理在所有停止判定前执行；政策失败先于偶然满足其他目标，正常目标成功先于 FP=0 的资源失败。

固定宏路线在全部 FP 上相同，改变评分权重只能改变最终选路，不能在路线中插入按剩余 FP 重选动作。默认评分 1–63 等权；失败成本、条件成功均值和零成功 N/A有独立手算例。原有退款／产出合成例仅检验记账算术，不赋予材料评分或库存功能。

## 用户7710完整路线回归

将[用户两条准备路线](examples/7710-to-target-double-t7.md)设为必需覆盖：先补A→封印→补B→最终浩劫，以及补A→按B侧T1垃圾子目标预浩劫→封印→补B→最终浩劫。正常加词进入原生费用／暴击联合核；保留补词后A或垃圾变T2、最终再补B的额外分支。

检查4普通栏T1必封与原垃圾被暴击升T2后不再必封的区别；检查准备浩劫不改词缀身份／前后缀、必须在B侧选垃圾；封印成功但FP归零无法再补词；最终达标优先于FP耗尽。已有目标和空侧不符必须拒绝无效添加候选，不能据此宣称所有路线无解。

完整参考动态规划用向外舍入区间包围数值误差，有限洗牌保护尾项及随机原语假设单列。独立逐步采样器不导入该评价器或其转移核；在两条主路线、三类FP、假设预算10/30/63的18点各抽样20000次，按预先固定5σ+1/N检验成功率。记录材料代价已从政策、接口、评分和候选剪枝删除。

剪枝与小规模完整搜索对照。完成只证明公开候选语言／宏阶段上限内的最优；预算耗尽不等于证明无解。未支持动作引起的不可达与物理上不可能分开。

## 常见771x及复杂7732回归

[常见模式](examples/common-crafting-patterns.md)新增已有A@T7、缺B的两类固定路线：直接封印→补B→浩劫，及准备浩劫→封印→补B→最终浩劫。x=1…7分别保留，x=7为三条T7；A不被重复添加、不被封印，准备中A的阶数可以变化。手算布局检查覆盖7711、7713、7717的重复阶数与子目标命中数。

14个有效输入及1个三栏不完整路线负例，三类FP与两个参考profile共90场景，均计算F=0…63。三栏不能被当作四栏排列；另以空侧兼容时补B→浩劫的正例检验，不能将7710模式整体标为不可达。

独立整路线抽样在x=1／3／7、两模式、三类FP、F=10／30／63的54点各20000次，共108万次，与参考DP按预先声明5σ+1/N标准核对。概率区间宽度、有限拒绝抽样尾项和原生随机流假设分别报告。

7732必须按目标身份分型。A、B已在T3／T2的最终浩劫，与独立77tu参考曲线对照；四个ID均非目标的指定合法手套例另执行[重复救赎](research/7732-feasibility.md)，验证逐槽动态排除池、一发正质量证据、8点共40万条完整路线、FP=0边界及普通／血同核。它是候选可达性基线，不是所有7732的统一概率或最优路线。

模式识别用于优先扩展，不能作为可行性白名单；尚未评价显示UNASSESSED，未完成搜索显示INCOMPLETE。只有公开模型与搜索范围内的不可达证明，才允许报告相应范围的无解。

## 独立验证与数值精度

资源 float32、原生 PRNG 格点／比较符号、独立连续数学模型分别记录。某个公式已核查不能直接标为客户端位级精确概率。

测试用 Fraction 手算小例，数值版检查概率和、线性系统残差及区间界。独立 Monte Carlo 不得仅从同一待测转移核抽样后自证；使用单独控制流实现和固定种子，事先指定置信区间与样本规模。参考计算器只对齐其版本／假设一致的输入，不作为替代原生证据。

## 浏览器与发布

首次性能检查提前到 Phase 2，完整求解器在 Phase 5 重测。测试 Worker 加载、任务取消／重启、旧结果隔离、模型不匹配、真实词缀池内存与普通／低性能设备。浏览器与 Node 同快照同输入的结果一致。

Pages 用实际仓库子路径检查入口、刷新、Worker、数据与版本。用户不输入实际 FP，计算中编辑不会被旧结果覆盖。线上托管验证不等于游戏客户端制作实测。
