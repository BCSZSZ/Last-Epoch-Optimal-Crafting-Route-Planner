# 中文词缀、详细输入与性能核对

本页为2026-11-06中文发布的历史记录。新程序求解器与实验前缀见[后续生产接入](production-programs-20261107.md)；Worker未变化的结论只适用于本页这一轮中文改动。

2026-11-06。生产机制与求解器仍为 `le-1.5.3-iid-b46d3015a01bbdb7`；实验求解器保留为独立对照，未接入Worker。

## 中文名称

界面原来只给少数ID提供中文，其余回退到客户端英文名。现在全部1156个词缀使用按数字ID索引的中文名称，覆盖普通、实验、神像及额外类型，名称不参与概率、资格或权重计算。

来源是本地已有冻结词库中的LETools Version1.5.0中文显示名；逐ID核对本地1.5.3快照的前后缀类型、特殊类型、职业限制及可用装备类型集合，1156项全部匹配。英文筛选显示名与客户端内部命名有392处差异，未用英文模糊匹配推断ID。翻译来源版本保留，不冒充本轮从1.5.3语言资源提取。

[独立名称来源](../data/localization/affix-names-source.json)、[生成的UI表](../src/generated/affix-names.zh-CN.json)、[匹配报告](../research/affix-localization.json)。运行时和重建验证均不依赖父项目、本机缓存或网络。`python -X utf8 scripts/build_affix_localization.py --verify-only`验证完整映射。

下拉列表与已选值显示中文；搜索接受中文、原英文和数字ID。原英文与ID保留在可选项提示中，便于核对。搜索索引按目录／ID缓存，避免每个按键重复组装名称。

## 详细输入的实际验证

六个本地静态页面／Worker导出均与Node的完整主路线报告、48FP结果逐位一致：[实际核对](../research/ui-validation/detailed-local-parity.json)。

新版已在GitHub Pages发布；公网实际操作完整指定7710、完整指定7271、部分通配目标三例，导出、显示指标及中文ID匹配均通过[公网复算](../research/ui-validation/detailed-public-parity.json)。中英文搜索返回相同ID，测试后恢复原输入。8个公网静态文件与构建字节相同；[发布记录](../research/deployment-detailed-locale.json)保留实际提交、工作流及版本。

| 输入 | 操作成功率 | 48FP整件完成率 | 成功路径平均FP |
|---|---:|---:|---:|
| 完整指定7710 | 100.00% | 68.34% | 48.80 |
| 完整指定7732 | 25.07% | 14.49% | 57.23 |
| 完整指定7271 | 84.50% | 50.55% | 55.68 |

所有起始身份完整且指定胸甲，使用真实制作权重的全职业通用池。身份留空目标是允许任意合法ID匹配，不表示一个尚未拥有的特定新词缀；空目标槽完全忽略。两项目标必须匹配不同物理词缀。

此外实际检查了中文／英文搜索返回相同ID、键盘选择、刷新保留模式／阶数／身份、超额T7目标阻止规划、编辑输入取消任务且旧结果不覆盖。回归覆盖错侧ID、重复目标ID、空目标、最低阶语义与独立封印目标。

测试中修正两处纯展示问题：初始剥离只列当前符合阶数的槽位；若浩劫不可能达到局部退出条件，后续程序永远不会执行，只展示其实际可达的全局目标停止条件。后一种情况曾让通配目标的结果多显示封印／补词。导出的原程序和数值计算保持原样。

发布前旧页面与新页面使用同一份完整7271输入，导出的主路线及48FP结果也逐位相同。

## 性能结果

同一台电脑、Node、每种输入先预热一次，再顺序测量5次，以下为中位耗时。普通桌面环境，非隔离的硬件性能实验。[测量记录](../research/detailed-performance.json)，复现`npx tsx scripts/benchmark_detailed.ts`。

| 输入 | 详细真实权重，生产求解 | 同ID等权对照，生产求解 | 实验求解器 |
|---|---:|---:|---:|
| 7710 | 435ms | 460ms | 63ms |
| 7732 | 3633ms | 3611ms | 368ms |
| 7271 | 9051ms | 9064ms | 31ms |

三例未显示详细身份／实际权重造成明显的额外退化；7271在两种模型下都达到当前生产搜索时间上限附近。生产搜索本身仍有耗时较长的候选，报告保留INCOMPLETE和预算停止原因。

实验求解器只覆盖添加／封印／剥离／浩劫及受限的最少开槽程序，生产求解还考察救赎／混沌等其他家族。耗时差不能解释为同一完整搜索范围的加速保证。

中文改动前后的生产Worker字节完全相同（SHA256 `99eefb97c61c2a7a22a8ab601dfe72621da9514549f1c9be93b77d5cf8e4e6cd`），没有把中文名称或索引加入计算线程。[构建体积对照](../research/localization-bundle-comparison.json)显示主界面脚本增加约13KB gzip；这属于加载数据增加，不是规划算法变化。未把静态文件大小解释为实测网络加载时间。

本轮机制、权重和规划请求保持原样，没有为缩短耗时改为等权或静默禁用动作。生产版7732仍是原有限候选中的结果；[实验方案](example-guided-solver-20261106.md)另有42.25%方案，尚待生产接入。

本机验证不代表低性能设备性能。该待验收项沿用用户此前约定。
