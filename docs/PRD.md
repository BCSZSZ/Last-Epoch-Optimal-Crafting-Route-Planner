# 产品需求：固定装备打造路线规划器

**当前生产实现**：[23节点求解器v2](hierarchical-solver-v2.md)已采用操作成功率＋成功路径FP期望及15%／65FP门槛，覆盖下文旧有限FP主评分。下文假设FP曲线等属于原始需求／旧研究基线，不冒充新版主报告。

状态：Phase 0 研究与数学架构审阅稿。日期：2026-11-03，日本时间。

## 产品目标

面向《最后纪元》玩家，为一件给定装备计算起点至目标的一条主推荐路线。起点与目标可精确指定词缀、最低阶数、可接受替代项、封印要求、保护要求和可选 roll 限制。起始装备的 FP 类型必须明确；实际剩余 FP 不作为必填输入。结果展示一组假设初始 FP 下的成功率及消耗，不要求玩家回填每次游戏制作结果。

输入不是自然掉落模型。不会把某个假设 FP 区间解释为这件装备的实际剩余 FP，也不优化购买替换底材的无限重复生产。

## 本轮已确定的产品政策

1. 所有操作先完整执行原生转移和费用／材料后处理，再判断产品停止条件。
2. 剥离未命中宏预先声明的允许删除集合，即判该路线失败；保留该笔已发生的真实装备变化与消耗，不执行后续宏。
3. 必要封印的一次检定未成功，即判路线失败；不追加封印重试或补救。失败后的原生加阶、可能暴击与退款仍计入该失败叶。
4. 浩劫和救赎等重复行为聚合为宏动作；宏内提前声明继续、成功和失败条件。
5. 主路线的宏顺序、目标选择及支持材料选择在计算前固定。仅允许预先定义的跳过、成功停手和失败退出，不根据途中结果另行搜索路线。
6. 首版动作集合包括添加／升级、希望、绝望、浩劫、救赎、混沌、剥离；三种 FP 分别建模。精炼、塑形、进化等保留扩展位置，不把未实现动作计入搜索覆盖。
7. 所有词缀碎片、符文和雕文固定为无限供应，材料代价不进入优化或同分排序。这是当前产品模型，不是可由玩家切换的库存选项；材料种类及原生支持资格仍决定实际转移。

## 输入与结果

输入包含完整装备状态、角色制作等级、目标和可选保护／操作限制。没有物理库存、材料价格或材料消耗上限字段；无限物料也不意味着 FP 无限。内部研究／高级调用如明确设置最多尝试次数，应作为独立操作限制公开，不要求网页用户填入。

结果包含主推荐宏序列、各宏停止条件、尝试次数、FP 消耗分布、成功率曲线、评分约定、模型版本、计算精度和搜索完成状态。材料消耗、退款和产出最多作为研究诊断，不形成目标、费用或用户决策门槛。无法达成的目标与搜索未完成必须分别说明。零成功概率时成功条件指标不适用。

排序依次为跨 FP 成功率、成功条件期望 FP、失败 FP 浪费、成功条件 P95／P90、宏阶段数和稳定编码；不比较材料数量或其价格，也不把尝试数当成材料代价的替代项。

## 先判断目标身份是否齐全

阶数短记号不能决定目标身份是否齐全。“两条 T7 都不是所需”可能仅指高阶两条：例如 7732 中 A 已在 T3、B 已在 T2，此时身份已齐，优先生成 FINAL_HAVOC 直到 A／B 双 T7 的基线，不能误判为必须先搜身份。若 A／B 在任意两条普通栏中都已齐备，不重复 ADD_A／ADD_B；已满足最终阶数时返回空路线。

只有实际四个 ID 都不包含 A／B 时，才属于两目标完全缺失的身份搜索。模式识别先读取实际 ID，再读取阶数、侧别和资格；不能用“7732”直接代表复杂或不可行。

## 用户最常见的已有 A：771x 模式

四个普通未封印栏位的阶数记为 771x，且其中一个 T7 已是目标 A、尚缺目标 B。它是用户常见模式，与下节 A／B 都缺的 7710 分开处理。x 必须记录实际值 1…7；x=7 是三个 T7 的有效边界，不能裁掉或套用其他 x 的概率。

- B 所需侧已有可封垃圾 T1：一次封印该垃圾 → 添加 B → 最终浩劫直到 A／B 普通栏各恰好 T7。
- 垃圾 T1 在错侧：准备浩劫直到 B 所需侧有可封的非 A／B 垃圾 T1 → 一次封印 → 添加 B → 最终浩劫。

已有 A 不重复执行 ADD_A。这两条候选的选择器排除 A，不封印／删除它；浩劫可以暂时把 A 的 T7 搬到别处，最终再满足目标。这里的保留方式不自动成为整个搜索的硬保护；只有用户明确要求全程保护身份、阶数或 roll 时，才据此限制其他候选。没有硬保护时，通用搜索仍可比较暂时改掉 A 后重新获得 A 的合法固定路线。

x=0 是三条普通词缀与一个空栏，不能当作四栏：只封印再添加 B 仍只有三栏，不能接浩劫。必须先判断是否可直接把 B 加入现有空栏；否则将额外补栏和必要准备纳入候选。完整模式、资格及边界见[常见打造模式](examples/common-crafting-patterns.md)。

## A／B 都缺：用户指定的 7710 算法校验

固定起点含两个普通未封印 T7 和一个垃圾 T1，另有一个空普通栏；A、B 是尚未具备、与实际底材和侧别兼容的目标 ID，普通封印槽空。成功标准为 A、B 都在普通未封印栏且各恰好 T7。

必须评价两条路线：

- 侧别合适：添加 A → 一次封印垃圾 → 添加 B → 浩劫直到 A／B 双 T7。
- 侧别不合：添加 A → 准备浩劫，直到 B 所需侧存在可封垃圾 T1 → 一次封印该侧垃圾 → 添加 B → 最终浩劫直到 A／B 双 T7。

准备浩劫的局部退出条件与最终目标分别表达。封印按声明的侧别、垃圾／可封／阶数条件筛选，再选择原生列表序号最小的对象；不能只从最终目标池选对象。添加引发的暴击可能改变新增或已有低阶词缀，必须按所有结果分支重算封印阶数与费用，不能把“初始垃圾 T1”当成全程 T1 保证。

这两条路线是算法模型验收案例，不预先宣称其对全部输入全局最优。实际选择的底材、ID、原生顺序、支持雕文和玩家等级应随研究结果固定记录。

## 模式基线与通用搜索

身份齐全的最终浩劫、771x 已有 A 以及 7710 两目标都缺的路线是候选优先展开和模型验收基线，不是仅允许这些输入的白名单。用户尚未系统评价的 7732 两目标在四个 ID 中都缺失等起点不能因此被判不可行；救赎、封印、混沌及其合法组合仍属于通用候选范围，受实际 ID、侧别、保护和原生资格约束。

未评价的模式记录 UNASSESSED，搜索尚未穷尽记录 INCOMPLETE；都不等于 IMPOSSIBLE。只有在公开操作／宏语言范围内有不可达证明，才可给出对应范围的不可达结论。

## 技术与交付

React、TypeScript、Vite 为首选。规则、宏与搜索为独立模块，浏览器 Worker 承载计算，界面只调用统一异步规划接口。首选 GitHub Pages；如私有仓库不具备 Pages 资格，用户已授权当前仓库改为公开。数学架构确需 Python 且资源测试通过时评估 Streamlit，再使用自有 AWS。

本轮交付研究快照、证据、复现脚本和规范规定的 11 份文档，以 7710 及已有 A 的 771x 常见路线检查联合概率与 FP 评价，并明确登记尚未评价的模式。生产搜索器、网页与部署在本阶段审阅后实施；研究脚本不是已完成的产品引擎。BOOTSTRAP 原文保留，本节用户修订优先于其中旧材料代价条款。

## 验收

概率来自版本化原生／资源证据；限制不自动放宽；失败立即终止政策有独立测试；同输入和模型可复现；概率评价精度与最优性证明分开；界面无需实际剩余 FP 或逐步回填。详细矩阵见[验证计划](validation-plan.md)。
