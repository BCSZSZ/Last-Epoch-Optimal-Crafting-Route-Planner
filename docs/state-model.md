# 状态、目标与异步规划接口

## 模块外部接口

界面只使用异步规划接口 `plan(request, {signal, onProgress}) -> Promise<PlanReport>`。浏览器 Adapter 将主线程的回调和取消信号转换为 Worker 数据消息；函数和 AbortSignal 不直接通过 Worker 传递。未来 Node.js Adapter 使用同一请求／报告契约，生产核心不依赖 React、DOM、网络或存储。

`PlanRequest` 包含 `modelId`、`item`、`craftingContext`、`target`、`constraints` 和 `scoring`。`item` 不含必填的实际剩余 FP；请求中没有实际库存、材料价格或材料消耗上限。内部 `EvaluationState` 加入 `hypotheticalFP`、宏阶段和局部宏控制状态；仅在明确声明操作次数限制时增加相应余额。请求的模型修订锁定整个计算，不能中途切换数据库。

## 装备状态

- 底材用 `(baseTypeId, subTypeId)` 标识，不能仅用本地化名称；同时保留物品类别、稀有度、实际物品等级、需求与职业限制。
- 每条词缀保留原生列表顺序、稳定 ID、显示阶数与原生存储阶数的明确转换、roll 原始字节／分量及特殊类别。不可按 ID 排序后丢掉顺序。
- 前后缀、普通封印、先古 T8 封印、腐化槽分别表达；实验、冠军等特殊类别不靠名称判断。目标指定匹配的槽角色，不能把封印 T7 混为普通栏 T7。
- FP 类型为普通／血／冰，映射以原生枚举及序列化审计为准。持久化普通装备 FP 为 0–63，见[打造审计](research/forge-fp-audit.md)；这不是掉落分布。
- 记录腐化、不可制作等会影响动作资格的原生标志。数据库中存在的底材或词缀不自动等于该动作可使用。

`craftingContext.playerLevel` 是必要的制作上下文：普通加阶资格与额外暴击升阶实际读取角色等级，不默认 100。研究期间先完整确定代码依赖；不在本阶段扩展隐藏信息的输入／展示方案。

## 固定无限物料与操作限制

用户最新约定：所有词缀碎片、符文和雕文固定无限。材料可用性是只读模型政策 `UNLIMITED`，不提供可填写的 inventory、price 或 maxConsumed。状态键不包含不断递减的物理库存，制作也不因材料耗尽而终止。

本地代码中 CheckForShard、暴击返还主材料、支持雕文保留等事实继续保存在原生审计。当前无限物料模型下，对应存在性检查按始终有货求值；混沌禁暴击、成功封印跳过暴击等其他资格不会被消除。支持雕文类型、符文类型及其合法组合仍是动作参数，不能把无限物料理解为可以同时叠加多个不兼容支持物。

可选的 `operationLimits.maxAttempts` 是独立操作次数限制，按开始一次完整制作累计，退款不会倒扣次数；默认未设置，网页无需要求用户输入。搜索时间／节点预算是计算执行限制，导致 INCOMPLETE，不能被偷换成装备制作次数限制。任何此类显式操作限制须进入缓存键和最优性 scope。

## 目标与保护

目标支持所需 ID、最低阶数、可接受 ID 集合、普通／封印槽要求、可选 roll 限制及不受约束的空余项目。“可选”不应生成必须满足的成功谓词。完全相同 ID 不应被多个互斥要求重复占用。

固定位置解释为稳定词缀／槽角色，不把 UI 当前排序当作游戏可操控位置。保护要求显式记录要保护的身份、阶数下界或 roll 属性；能够违反硬保护的动作不能作为合法候选。规则内未找到路径与全游戏不可能的结论分开。

先检查语法与数据库资格，再检查前后缀容量、封印容量、等级与操作集可达性。T7/T8 目标不能被普通升级凭空满足；未覆盖的精炼或进化目标应报告操作覆盖范围。

## 核心内部接口

原子转移输入完整 `EvaluationState`、固定动作及不可变机制快照，返回联合原子结果：概率、下一个完整状态、尝试次数、FP 变化、该笔原生结果标志及可选材料诊断。不要将“状态变化”和“平均扣费”独立返回后相乘。

材料记账仅可作为可选研究诊断，不扩张状态、不参与评分。必须保留由材料种类决定的原生机制，以及暴击同时改变阶数、FP 退款等联合效果。

## 中间准备状态与选择器

终局谓词 `target` 与宏局部谓词 `subgoal` 分开。HAVOC_UNTIL 可以以“B 所需前／后缀侧至少有一个当前 T1、非 A／B／保护对象且可封的垃圾”为准备 subgoal，不必每次都以最终 A／B 双 T7 为退出条件。

`FIRST_SEALABLE_GARBAGE_ON_SIDE` 先按固定 side、排除 ID／保护对象、原生可封条件及声明的 tierPredicate 过滤，随后取最低原生列表序号。不能先按 UI 排序、ID 或阶数重新排序后选取。需要 T1 的准备路线显式带 T1 条件；直达路线则按添加后对象的真实阶数执行封印，原来的 T1 被暴击升成 T2 时不能继续套 T1 参数。

选择器及 subgoal 在规划前固定，对每条随机分支只是执行同一声明规则，不触发中途重新优化。添加、准备浩劫和最终浩劫中的 roll／阶数变化均留在完整状态中。

宏与路线评价消费该联合分布。报告不回传整个搜索状态树，只返回推荐、曲线、分布摘要、证据与计算状态。进度包含任务 ID；取消或新请求到来后旧任务不能覆盖新报告。同步重计算中使用协作式让出执行权，或由 Adapter 终止 Worker 并重新初始化，不能仅发送无法被处理的取消消息。

## 精度与搜索状态

`evaluationStatus` 描述按哪个随机原语模型精确求解、近似及误差；`searchStatus` 描述候选语言是否穷尽；`optimality` 描述证明范围。三个概念不得互相代替。方法地址登记也不等于其全部行为已验证。
