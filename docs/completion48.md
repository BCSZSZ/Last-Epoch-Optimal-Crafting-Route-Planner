# 成功率、48FP整件完成率与推荐标记

2026-11-04。用户确认保留65FP放弃门槛，新增固定起始48FP的整件完成率。

## 显示和判定

结果显示成功率、整件完成率（48FP）和成功路径平均FP。

- 成功率：FP持续充足时的操作成功率，剥离误删、必要封印失败等NG计入。
- 整件完成率：同一完整固定路线，从48FP出发，在操作NG或FP耗尽前完成完整目标的概率。
- 成功路径平均FP：不截断余额，只统计最终操作成功路径，仍用于65FP门槛。
- 整件率上界低于25%标不推荐，下界高于65%标推荐。恰好25%和65%中性；区间跨阈值待确定。必要时显示“>65%／<25%”，避免两位小数掩盖严格边界。
- 已放弃路线不追加整件评价，整件率显示未计算，不能拿前缀数值当完整完成率。

原候选排序保留：通过门槛后先比较操作成功率，再比较成功路径平均FP。48FP决定额外推荐标签，没有扩展为按整件率重排全部候选。中间区间显示“当前方案”。

## 数学与执行

`RuleEngine.budgetTransition`从同一动作实现生成状态变化和条件余额核，保留暴击、额外升阶、退款与出口的关联；兼容出口共享费用核，不用平均费用替代随机费用。

`completion.ts`编译固定分支，保留ID、原生顺序、阶数、封印、保护、roll和尝试次数。逐余额递推；同余额免费回路写成`(I-Q0)v=b`。用向外舍入残差和`h≥1+Q0h`证书包围误差，不把固定迭代次数当作精确概率。动态救赎保留逐槽更新及已有ID排除；浩劫按不同阶数布局的完全图首次出口规律计算，没有忽略重复阶数。

动作完整结算后先处理必要NG，再判断目标。最后一次动作降至FP0仍可达标。希望／冰、幸运、暴击退款和1／2FP保留均在余额核内。

只评价最终主方案，避免将48余额轴乘到全部搜索候选。默认12秒总预算预留后25%给完成率；超出状态／时间预算显示未算完，不伪造概率或推荐标签。取消、任务ID和编辑隔离继续生效。
