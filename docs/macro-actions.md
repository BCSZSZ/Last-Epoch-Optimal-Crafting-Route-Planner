# 宏动作与固定路线契约

当前生产补充：[23节点求解器v2](hierarchical-solver-v2.md)新增预先声明的条件分支、按固定碎片顺序填充，以及明确窗口耗尽行为／浩劫恢复窗口的混沌宏。评价使用持续FP的操作成功率和成功路径FP，不在主指标中因余额耗尽而NG；下文涉及有限FP的部分保留为旧基线说明。

状态：Phase 0 架构审阅稿，2026-11-03。游戏资格与概率取自[动作审计](research/affix-actions-audit.md)和[费用审计](research/forge-fp-audit.md)，联合计算见[概率模型](probability-model.md)。

## 1. 固定路线的含义

路线是预先确定的有序宏序列 R=(m1,…,mL)。每个宏只执行声明的原子操作、目标选择器和支持物；读取实际状态是为了判断继续、成功、跳过或停止，不在过程中重新搜索动作、替换目标、交换阶段或按实际 FP 改选路线。

同一个 R 用于全部假设初始预算。只有达到目标即停止、资源／资格不足即停止、用户指定失手即失败等固定判定可以因状态不同而触发。路线中所有必要条件及停止规则会随结果一起输出，用户无需回到网页重算。

一个宏有小接口：入口状态和参数输入，返回带退出状态、原因、概率、奖励统计的核。原子尝试保留在其实现内；调用方不需要逐次驱动。

## 2. 公共定义

每个宏固定以下内容：kind、参数、actionSelector、entryPredicate、successPredicate、abortPredicate、nextStage。selector 若读取状态，只能使用该 kind 事先审阅的有限规则；不得是任意 callback 或隐藏的优化器。

“已有目标 A”与“需要添加目标 A”必须由入口状态区分。771x 已有 A@T7 时，本模式不重复 ADD_A，封印／移除选择器排除 A，允许浩劫临时改变 A 的 tier／roll。终局要求 A@T7 不等于全程身份、tier≥7 或 roll 的硬保护；只有用户明确设置的硬约束才限制整个搜索，其他合法路线不继承本候选自身的保留选择。

若 A／B 身份本已齐全，则先生成单个 FINAL_HAVOC 基线，不添加缺失身份步骤。例如 7732 的两条 T7 可能都是垃圾，而 A、B 正好位于 T3、T2；这与四个 ID 都非 A／B 的 7732 是不同入口。基线不是最优证明，其他合法候选不因此被裁剪。

局部 successPredicate 可表示中间准备状态，与整条路线的最终目标分开。HAVOC_UNTIL 必须支持“在所需侧制造一个可封垃圾 T1”等准备谓词，不仅支持最终目标 ID 都达到 T7。SEAL_ONCE 必须支持非最终目标对象：先按所需侧、垃圾身份、可封及声明阶数条件过滤，再选择最低原生列表索引；这条选择规则在规划前固定。

条件与选择器用可序列化的受限描述表达，并由固定版本的编译器解释。跨 Worker 只传数据；未知描述、未支持原子操作或不匹配模型版本直接拒绝。

进入宏时已满足本地子目标可零次退出；完整终局目标已满足则整条路线成功。途中额外加阶等副作用按联合原子核保留，不假设会回到宏入口装备。退出分布可以有多个装备状态，下一阶段分别从这些状态评价，但其宏定义和阶段顺序不变。

## 3. 首版宏集合

| kind | 固定行为 | 正常退出 | 失败退出 |
|---|---|---|---|
| ADD_AFFIX | 向声明合法空栏添加指定 ID，支持物固定 | 该次合法制作及后处理完成 | 无合法位置、FP 不足或保护冲突 |
| UPGRADE_UNTIL | 对声明 ID 重复同类升级，达到指定最低阶数 | 子目标达到；额外加阶结果完整保留 | 普通可制作上限、资源或资格阻止目标达到 |
| CHAOS_UNTIL | 对声明的可升级槽位重复混沌，目标候选集合固定 | 变为可接受 ID 且达到声明阶数条件 | 达普通升级上限仍未命中、资源或资格不足 |
| SEAL_ONCE | 用声明 ID 或固定侧别／垃圾选择器确定对象，只封印一次 | 本次确实封印了所需对象 | 未封印即 POLICY_ABORT，包括原生已经升级的分支；没有合法对象则资格失败 |
| REMOVE_ONCE | 只执行一次剥离，允许移除 ID／对象集合固定 | 移除对象属于声明允许集合 | 任意其他移除对象立即 POLICY_ABORT |
| HAVOC_UNTIL | 重复浩劫，局部准备／终局布置谓词固定 | 指定 subgoal 成立 | 资格或 FP 不足 |
| REDEMPTION_UNTIL | 重复救赎，所需崇高身份／阶数谓词固定 | 指定词缀配置成立 | 资格或资源不足 |

ADD_AFFIX 是一次原子制作；“替换所需词缀”由明确的 CHAOS_UNTIL、SEAL_ONCE→ADD_AFFIX 或 REMOVE_ONCE→ADD_AFFIX 序列组成，不能把各自风险隐藏为一个必定替换成功的按钮。保护约束在候选生成与原子资格两处检查。

所有碎片、符文和雕文固定无限，材料数量不限制宏。Havoc／Redemption 默认不指定人为固定尝试次数，以 FP、目标或原生资格构成停止规则；独立明确设置的操作次数上限可作为附加限制，但不强加给界面用户。必要封印不因此获得第二次机会；剥离也不因物料无限而自动再剥一次。

## 4. 条件与次数

需要区分三类“失败”：本次浩劫／救赎未命中目标但仍可继续；必要封印／剥离的用户终止失败；原生操作根本不合法。只在第一类继续同一宏。每一类都保留已发生的 FP、材料与装备变化。

几何分布仅在已证明所有未成功状态对未来操作完全等价、单次成功率固定，且资源与停止规则不破坏该等价性时使用。实际 FP 有限时，即使单发命中率固定，也不能把无限预算的 1/p 直接当作该宏实际期望次数。

Redemption／Chaos 等身份变化通常会改变排除集合及下一次候选概率；Havoc 不同未成功布置也未必等价。默认使用显式状态转移，经证明的对称状态才可合并。

## 5. 输出与可读路线

每个宏输出阶段名、固定参数、作用对象或选择器、成功／继续／退出规则、到达该阶段概率、尝试数期望和净 FP 消耗。材料 consumed、退款和额外产出可作可选诊断，不参与选择或排序。条件到达后的指标与全路线无条件贡献分别命名，不能将它们相加混用。

当前实现的`macroStatistics`分别返回`reachedProbability`、`executedProbability`、`expectedAttempts`、`expectedFp`以及两个`GivenReached`条件均值。到达表示进入本阶段检查，包括无需执行的跳过及FP不足；实际执行表示至少发生一次合法制作。全路线已提前达标不再到达后续阶段。前两项是事件概率，只能计一次；尝试数及净FP是可累加奖励。重复宏和浩劫闭环同样保留这一区别。概率下界为0时条件指标返回null。

尝试数表示执行了多少次原子制作，不因暴击返还材料而减少；诊断耗材 consumed=debit−refund。剥离碎片产出单列，不定价。支持物类别决定的原生转移继续执行，critical 的 FP 退款不能因材料免费而忽略。

## 6. 两条 7710 必需校验路线

两条路线均固定普通未封印目标 A、B，成功要求各恰好 T7。起始普通栏是两条垃圾 T7＋一条垃圾 T1＋一个空栏，封印槽空。实际底材、侧别、角色等级、原生列表及每阶段支持物全部随案例记录。

### 路线 D：侧别直接适合

~~~text
ADD_AFFIX(A)
SEAL_ONCE(FIRST_SEALABLE_GARBAGE_ON_SIDE(side(B), exclude={A,B,protected}))
ADD_AFFIX(B)
HAVOC_UNTIL(A@ordinaryT7 AND B@ordinaryT7)
~~~

添加 A 后原垃圾不保证仍为 T1：额外暴击可能改变 A 或垃圾的阶数，也可能退 FP。封印选择器按当前真实阶数验证资格并使用当前阶数概率／费用；不能把全部质量投向“封印 T1 必成”的简化分支。封印未中直接失败，不在升阶后再封一次。

### 路线 P：先搬出可用封印位

~~~text
ADD_AFFIX(A)
HAVOC_UNTIL(exists garbage on side(B)
            with currentTier=1 and sealable and id not in {A,B,protected})
SEAL_ONCE(FIRST_SEALABLE_GARBAGE_ON_SIDE(side(B), tier=1,
          exclude={A,B,protected}))
ADD_AFFIX(B)
HAVOC_UNTIL(A@ordinaryT7 AND B@ordinaryT7)
~~~

准备浩劫不改变身份，其固定子目标只负责让 B 所需侧腾位可行；它可能改变 A 和其他词缀阶数。已满足该子目标时准备宏零次退出。存在多个合格垃圾时按原生序号选最小者，不按运行时估算再择优。最终浩劫从添加 B 完整后处理后的实际状态分布出发，不能硬设为 7711、7712 或某个固定单发成功率。

两条路线均是强制覆盖的候选与评价案例，不预断全局最优。准备宏用尽 FP、没有可封对象或封印失手都会保留其失败质量；不能只报告准备成功条件下的最终概率。

## 7. 已有 A@T7、缺 B 的 771x 基线

本模式的四条普通词缀为 771x，x 分别取 1…7，A 已占其中一条 T7。封印槽空，B 与底材及声明侧别兼容。x=7 是三个 T7；不同 x 保留各自阶数与转移，不能使用一份不区分 x 的固定概率表。

### B 所需侧有垃圾 T1

~~~text
SEAL_ONCE(FIRST_SEALABLE_GARBAGE_ON_SIDE(side(B), tier=1,
          exclude={A,B,protected}))
ADD_AFFIX(B)
HAVOC_UNTIL(A@ordinaryT7 AND B@ordinaryT7)
~~~

### T1 在错侧

~~~text
HAVOC_UNTIL(exists garbage on side(B)
            with currentTier=1 and sealable and id not in {A,B,protected})
SEAL_ONCE(FIRST_SEALABLE_GARBAGE_ON_SIDE(side(B), tier=1,
          exclude={A,B,protected}))
ADD_AFFIX(B)
HAVOC_UNTIL(A@ordinaryT7 AND B@ordinaryT7)
~~~

准备浩劫可把 A 的 T7 暂时移走，但不改变其身份。本模式不为腾位封印 A，也不能把救赎视为可单独锁住 A 的 T7。只有用户明确设置 A 的全程身份硬保护时，才据此拒绝可能改掉 A 的其他路线；否则可比较暂时更换后重新获得 A 的合法路线，不能假装救赎始终保住它。添加 B 后继续保留暴击及 FP 退款导致的真实分支。

x=0 只有三条普通词缀：SEAL→ADD_B 后仍为三条，必须补到四条才允许执行最终浩劫。若 B 可直接填入原空栏，应保留 ADD_B→FINAL_HAVOC 候选；若仍需封印腾出 B 侧位置，则为剩余空栏增加合法填充 C，并把该步及其副作用计入路线。不能仅因短记号形似 771x 就跳过栏位计数。

这些模式只用于优先生成和验证候选。7732 等 A／B 都缺的起点，仍可由其他合法宏组合评价；没有匹配的常见模式不能成为全局失败条件。详细资格见[常见打造模式](examples/common-crafting-patterns.md)。

## 8. 验收案例

- 必要封印第一次未成功：即使剩余 FP 足够且后续升级合法，整个路线后续动作次数为零。
- 剥离删错：即使还可以补回，整个路线失败，不执行 ADD_AFFIX。
- 浩劫未命中但仍合法：继续同一宏，按 FP 与装备更新后的状态进入下一次。
- 救赎顺序与当前 ID 集合变化：下一次核使用新状态，不复用入口的一发概率。
- 子目标因上一步暴击已满足：跳过该宏；完整终局目标达到则整条路线立即成功。
- 最后一发达到目标且 FP 归零：成功；未达到目标则资源失败。
- 封印成功但 FP 归零、还需补词：不能把局部封印成功当整条路线成功。
- 一个闭合零消耗未命中类：报告非终止，不假设最终一定成功。
- 771x 已有 A@T7：没有 ADD_A，准备浩劫可移动 A 的 tier，封印／移除选择器始终排除 A。
- x=1…7 逐值检验；x=7 保留三个 T7，x=0 单独验证三栏及必要补栏。
- 没有常见模式覆盖的 7732：保持 UNASSESSED／INCOMPLETE，不从未列入模式推出 IMPOSSIBLE。
