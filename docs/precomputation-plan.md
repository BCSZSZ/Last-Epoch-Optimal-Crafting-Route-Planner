# 预计算结论与极简输入的影响

2026-11-03。值得做，常见路径可逐步变为查表。此次先实现用户要求的UI与输入契约；下面是后续设计，未实现离线查表，未宣称预计算后的加速比。

## 实施方向

1. 最终／准备浩劫、封印、剥离、添加／升级建立小型退出核，保存每个出口概率`K`及FP首矩`R=E[C·1出口]`，正确连接最终成功条件费用。
2. 普通匿名身份按前后缀、T级、目标角色、普通占用、封印占用规范化。离线评价有限完整模板，保存Pareto候选和适用条件。23标签用于路由，不能单独作为数值键。
3. 救赎／混沌按池签名、权重类、目标角色、固定排除身份与原生顺序分块。等权模式保留候选数量及排除角色等经证明充分的信息；具体身份模式在浏览器补算该段，再连接预计算后缀。
4. 复用同一吸收系统的图／求解信息。所有分支和后缀仍预先固定，不按随机出口临时选最优后缀。
5. 版本化索引与分片懒加载，同机缓存完整结果。未覆盖／未完成条目回退当前求解，不将缓存未命中判为“已放弃”。

## 新输入契约的收益

默认可锻造，不再对角色等级、物品等级和具体底材建立乘积表。简易目标只保留前后缀数及已有身份进度；匿名身份无需枚举1156个名字。输入顺序固定为前1、前2、后1、后2，不能据此宣称实际所有原生排列等价。

恰好两个普通T7，其余两普通位置为“空／T1…T6”，位置化阶数布局仅`C(4,2)×7²=294`种；两条非空低阶多重集21种、四条布局216种。294尚未乘目标角色、封印、部位池和FP状态，不是完整表大小。无需身份抽选的等价核可以跨部位复用。

[容量脚本](../scripts/analyze_precomputation.py)对完整原接口估算：8580规范结构乘两个封印标志、两个暴击制度为34320个容量代表。每条假设64字节约2.09MiB；再乘24原生顺序、四条Pareto候选约201MiB。只是容量情景，不是已证明等价类数或实测编码体积。反之，字面枚举具体装备／目标ID的窄子集已约1.794×10¹³格，两float64约261TiB，说明应压缩规律。完整接口估算不是极简页面必须承担的状态量。

同一无余额固定路线，普通／冰潜能共享概率核，冰FP首矩为普通的0.7；血潜能影响普通暴击，需独立核。普通超过65的提前截断记录不能直接作为冰的放弃结论：普通完整均值90对应冰63。

## 优化顺序

[源码审计](research/precomputation-source-audit.md)发现每个模板／前缀仍建图并重复解同一系统，再解总费用。旧模型的[剖析调用记录](../research/precomputation-runtime-profile.json)中，7713主路线33状态而整次约7.06秒，7732主路线1737状态而整次约2.96秒。主路线很小，也不代表竞争模板和未完成候选免费。这是旧模型的具体测量，不据此推算预计算加速比。

先复用图／退出核及常用完整模板表，再做权重类救赎块。用相同固定候选集验证数值、放弃判定和覆盖范围一致，分别衡量加载、查表、补算耗时及体积；不以减少候选冒充提速。
