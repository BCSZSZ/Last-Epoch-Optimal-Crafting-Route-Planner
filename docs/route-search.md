# 固定路线搜索与最优性范围

状态：Phase 0 架构审阅稿，2026-11-03。依据[启动规范第 7–8 节](../BOOTSTRAP.md)、[宏动作契约](macro-actions.md)、[概率模型](probability-model.md)与[优化目标](optimization-objective.md)。

## 1. 搜索对象

候选是固定宏序列，不是“装备状态 → 最优下一步”的自适应策略。一个候选在全部假设 FP 上独立传播分布，最后由同一个评分配置统一比较。

宏动作参数来自有限的已支持操作、输入目标和候选词缀／槽位集合；具体生成器版本进入搜索范围标识。初始草案默认 macroStageLimit=12，允许显式配置。这个值是产品搜索预算，不是游戏规则，也不证明更长路线无用。

任何按目标缩减的候选池都需证明：未列出的填充词缀／中间身份不会通过封印、混沌、浩劫、已有 ID 排除或额外加阶改变后续结果。无此证明时，要么保留候选，要么明确写为受限候选集；不能只保留最终目标 ID 后声称覆盖整个游戏。

重复动作由宏内部停止规则吸收，不使用“每个宏最多尝试 N 次”替代原生资源停止。阶段上限与用户显式尝试／库存限制是不同约束。

## 2. 基线算法与数据流

1. 校验版本、起始装备、目标与限制，编译终局谓词和有限宏候选语言。
2. 以空路线作为根，展开长度不超过阶段上限的宏前缀。
3. 对各 F 保存前缀结束后的联合状态分布、已吸收成功／失败质量、成本及材料所需统计。
4. 接一个宏时组合其退出核，更新分布与奖励；所有已失败质量保持吸收。
5. 得到满足完整目标的候选后，按词典序更新当前主推荐和内部 Pareto 集合。
6. 搜索结束时同时输出候选语言／上限、节点数、未展开前沿、完成状态及可证界。

开发从小规模完整枚举开始，建立可核对的正确性基线。上线搜索再加入记忆化、状态驻留、分支定界和经证明的支配剪枝；不能先写复杂剪枝，再只用同一实现验证自身。

同一固定前缀会产生多个随机状态。下一宏必须对这整份分布使用同一个定义，不允许为分布中的每个状态各选最佳宏再拼回。后者构造的是可观察状态自适应策略。

## 3. 记忆化和状态规范化

缓存键至少含机制快照 ID、装备完整语义状态、假设 FP、当前宏及控制状态、玩家等级上下文、实际 inventory 与独立 usageLimits。实际库存可通过关键材料向量压缩，但不能用“材料不限”结果缓存覆盖有限库存结果，也不能以用户剩余次数代替决定原生 critical 资格的仓储余额。

显示名不进入状态身份；稳定词缀 ID、原生列表顺序、roll、特殊类别、独立封印槽等会影响转移的属性进入状态键。只有已有证明的语义等价状态才能合并。相同 tier 多重集或相同终局成功率，不足以证明两个状态等价。

缓存原子核、宏核和路线前缀评价可各自独立，不向 React 或 Worker 消息复制整个搜索树。候选排序、状态编码及终端分类均确定性；改变模型或搜索语义版本即失效旧缓存。

## 4. 安全剪枝

优先实现下列可证明规则：

- 完全相同的前缀联合状态与统计分布，保留宏阶段更少或完整排序更优者。
- 原生资格、硬保护约束、用户一次失败停止规则所禁止的动作直接排除。
- 对未吸收前沿给乐观成功界：假设所有仍存活质量以后都能免费成功。该 J 上界严格低于当前候选 J 下界时可剪枝。
- 更紧的可达性或费用下界，必须有独立证明和小模型穷举核对后才能加入。

仅“期望 FP 更低”“当前成功率更高”“每个 F 的前缀成功率都更高”都不足以支配任意后续：前缀留下的装备、库存和概率分布可能不同。只有对允许的全部共同后缀能保持目标序关系，才可在中间状态上做 Pareto 支配删除。

完整终态路线之间，可以用全部 F 的成功率及已定义排序指标保留 Pareto 候选；这个 Pareto 集合不能直接当成前缀剪枝证明。即使两个候选成功率相同，也须保留后续 tie 所需的成功条件矩与分布。

## 5. 完成状态和界

~~~text
evaluationStatus = EXACT_UNDER_MODEL | BOUNDED_NUMERICAL | ESTIMATED
searchStatus = COMPLETE | INCOMPLETE
scope = { modelId, rngModel, operationSet, macroLanguageVersion,
          macroStageLimit, candidateRestrictionId, materialConstraints,
          scoringConfiguration }
~~~

COMPLETE 表示该有限 scope 的所有候选已评价或被安全证明排除；只在此范围内声明最优。没有阶段上限的全局最优必须另有“更长序列无改进”的证明，不能由本搜索完成状态推出。

时间／内存／用户取消等停止搜索时，标 INCOMPLETE。已找到的可行候选可返回为“当前已找到的最佳路线”，不能标为已证明最优；无候选时返回“尚未找到”，不声称目标不可达。若前沿上界可计算，给出全局评分上界、当前候选下界与差距；缺乏有效界时相应字段为 null。

高分位与其他 tie 指标在主评分界重叠时同样影响最优证明。只有 J 的上下界相等，仍不能忽略 tie 未完成而声称排序已证实。

## 6. 浏览器与服务端执行

React 只调用统一异步规划接口，Worker 适配器管理启动、进度和取消。取消必须能中止长时间同步搜索：使用分批让出事件循环并检查取消，或终止并重建专用 Worker，不能只发一条永远没机会处理的 cancel 消息。

核心计算不导入 DOM、React 或 Worker 对象；以后 Node 适配器复用同一规则和评分模块。浏览器性能评估与 Node 使用相同快照、输入、scope 和结果口径，避免将缩小搜索范围产生的速度提升解释为平台优势。

首版并行搜索只有在分区完整性、合并排序和概率数值可复现性经过验证后启用。先把 Worker 用于保持界面响应，不承诺仅靠 Worker 就能解决状态爆炸。

## 7. 必需验证

小模型逐条枚举所有 scope 内宏序列，与优化后搜索比较主推荐、Pareto 集合和未达标分类。特意加入“均值较好但未来分布较坏”“逐预算最优路线不同”“罕见状态决定后续可达性”的反例，防止非法剪枝或自适应包络。

性能基准包含真实词缀池下的双 T7 浩劫、稀有救赎目标、必要封印／剥离前置及三类 FP。报告模型版本、搜索限制、评价精度、时间、内存、节点数、取消响应和浏览器／Node 一致性，不用玩具模型耗时承诺完整游戏性能。
