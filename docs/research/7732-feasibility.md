# 7732分型与重复救赎可达性基线

日期：2026-11-03，日本时间。研究前重新执行当前游戏提取的`--verify-only`，1.5.3／Steam build26087601的DLL、元数据及资源快照核对通过；DLL SHA-256为`323e9183f3bee600b6c9e1c469218b9de926e9044f2ca3d44fae8a0ec9a91464`。本页是当前原生资格与版本化资源支持的参考计算，没有客户端制作频次实测。

## 1. 7732并不是一个完整概率输入

7732只说明四条普通未封印词缀的阶数多重集。还要区分目标身份、前后缀侧别、底材与具体ID：

| 目标在起始装备中的位置 | 可以明确说什么 |
|---|---|
| A、B已经是两条普通T7 | 目标已完成，无需打造；包括FP为0时也不需要尝试动作 |
| 两条T7不是目标，但A、B身份已经在普通T3／T2或其他普通位置上 | 可以直接研究浩劫搬阶；本阶数族为77tu，未达标状态的标称单发目标布局率2/11，已有参考验证。它不需要先用救赎搜出A、B |
| 只有一个目标身份已存在 | 需要按其位置、侧别及允许操作另算；救赎也会改掉现有好T7，不能假定锁住它 |
| 四个初始ID都不是A、B | 本页下述基线仅核算其中一个合法实例，不能推广为所有此类7732的统一成功率 |

所以“两个T7没命中目标”不等于“两个目标身份都不在物品上”，也不等于“7732不可达”。若仅凭人脑不容易估计，程序应完整枚举／采样实际状态，而不是将复杂性当成不可行证据。

## 2. 本页唯一的完整输入与路线

本例使用普通手套`4:0`（Hide Gloves）、角色100级、未腐化、四条普通未封印词缀，材料统一无限，始终配希望雕文；不输入库存或材料价格。

| 位置 | 初始词缀 | 目标 |
|---|---|---|
| 前缀1 | ID2近战攻击速度T7 | A=ID4施法速度T7 |
| 前缀2 | ID26召唤物伤害T7 | B=ID5暴击几率T7 |
| 后缀1 | ID7虚空抗性T3 | 无要求，保持身份与阶数 |
| 后缀2 | ID10腐化抗性T2 | 无要求，保持身份与阶数 |

四个初始ID确实均非A／B。目标A、B在本底材上兼容且都是前缀；初始两条T7也在前缀，所以救赎能直接将它们改成目标身份。若把初始两条T7改成后缀而目标仍为前缀，就不能沿用这里的救赎基线。

固定路线：**对当前物品反复使用救赎＋希望，直到一次完整符文动作结束后A、B都为普通未封印T7；否则只要FP仍大于0就继续，耗尽则失败。**不买新底材、不回到起点、不追加别的符文或自适应换路线。救赎保持阶数／roll，故整个过程中普通阶数仍为7732，后缀ID7／10不参与重抽。

原生依据见[词缀操作审计](affix-actions-audit.md)的救赎、候选池与权重，以及[FP审计](forge-fp-audit.md)的符文成本、希望／冰和公共低FP保留。单次救赎依序重抽两个T7，第二条必须读取第一条已更新后的完整ID排除集合。

## 3. 一发正概率足以证明此输入在模型内可达

脚本从当前快照重建40项普通通用手套前后缀池，使用实际float32制作权重的精确有理数表示，按每一步更新的排除集合展开两次前缀身份重抽。得到289个终态，概率质量精确等于1。

```text
P(第一发后A、B都为T7)
 = 140737488355328 / 16257994501799281
 ≈ 0.00865650977675952
 = 0.8656509777%
```

这是**独立归一化权重参考模型**的精确分数，原始参数与筛选规则来自当前本地游戏；不是原生PRNG位级路径或客户端频次的精确声明。原生格点、float32累计阈值及独立抽样的差别已在概率模型中另行标注。

只要起始FP大于0，这次合法符文会完整执行，即使其费用将FP耗尽，最终达标仍算成功。因此在本模型下，该固定输入与路线的成功质量至少包含这条一发正质量，不能称为不可达。材料昂贵也不能用作当前判定理由，因为本轮明确假设材料无限。

### 为什么不能把这次命中率固定下来套几何分布

同一池和其余后缀不变，只改变两个当前前缀ID及处理顺序，一发条件率就不同：

| 当前T7前缀顺序 | 一发后目标双T7 |
|---|---:|
| ID2、ID26 | 0.8656509777% |
| ID4、ID26 | 0.4328254888% |
| ID26、ID4 | 0% |

最后一种并不意味着以后永远不能成功，而是该状态下这一发的顺序与自身ID排除使本次无法同时命中。重试会改变下次的完整状态，不能用起始`p`直接计算`1-(1-p)^n`或`1/p`。也不能在符文只重抽完第一条、暂时出现目标组合时提前停止：该次救赎还必须继续处理第二条T7。

## 4. 完整重复路线的独立直接采样

本轮取普通／冰两种FP，各在假设起始FP为1、10、30、63时采样50000条完整路线，共400000条。每行固定独立种子，所有参数、输入文件哈希、样本数、成功数与统计量保存在[结构化结果](../../research/7732-redemption-reference.json)。

采样逐次执行：希望免费检定→若仍需扣费则冰潜能检定→救赎基础费用1–19及28.5%幸运费用重抽→依最新ID集合重抽两条T7→公共保留2／保留1的有序5%检定→完整结果达标或继续。幸运费用第二抽范围是`[1,第一次费用)`，不是再抽原始全范围；额度不足按实际FP截到0，最后一发仍可达标。

采样代码不导入路线DP，也不预先给定每发命中率。只缓存“当前完整ID排除集合对应的合法候选CDF”，每次第一条变更后立刻按新的集合处理第二条。FP为0时不执行符文；采样循环保护若触发会报错，不会偷偷截断并计为失败。

以下全为Monte Carlo估计；区间是每行二项成功率的双侧Wilson99%区间，不是8行联合99%保证，也不包括机制模型不确定度。实际FP均值包含失败路线；尝试均值包括零FP成本的重复。

| FP类型 | 假设起始FP | 成功率估计 | Wilson99%区间 | 平均实际FP消耗 | 平均救赎次数 |
|---|---:|---:|---:|---:|---:|
| 普通 | 1 | 1.064% | 0.952%–1.189% | 0.9975 | 1.3268 |
| 普通 | 10 | 1.966% | 1.812%–2.132% | 9.9325 | 2.5091 |
| 普通 | 30 | 4.212% | 3.987%–4.450% | 29.4554 | 5.5354 |
| 普通 | 63 | 7.608% | 7.308%–7.919% | 60.7760 | 10.3673 |
| 冰 | 1 | 1.588% | 1.450%–1.739% | 0.9930 | 1.8912 |
| 冰 | 10 | 2.694% | 2.514%–2.887% | 9.8695 | 3.5689 |
| 冰 | 30 | 5.656% | 5.396%–5.928% | 29.1942 | 7.7921 |
| 冰 | 63 | 10.396% | 10.050%–10.753% | 59.7324 | 14.5509 |

这里的FP点是程序内部的假设预算评价，不要求玩家输入实际剩余FP，也不是FP掉落分布。成功率不等于“推荐”或“实用”判定；本例尚未与其他合法固定路线比较。

## 5. 为什么本条符文路线血潜能与普通相同

当前Forge的普通／血暴击入口要求合资格主碎片ID；纯救赎符文路径没有该入口。血潜能因此不为每次救赎增加暴击、免费或额外重抽机会。其费用／身份核与普通相同；冰潜能则通过额外保留改变费用核。

在本页固定动作集与相同起始状态下，可以将血潜能曲线直接别名到普通曲线。这是相同转移核的结论，不是“血潜能在所有打造中都等同普通”。脚本另用相同随机数对普通／血的1000条完整路径进行逐条耦合校验，全部相同；表中没有冒称额外独立采样了血潜能八行结果。

## 6. 复现及边界

只需Python标准库，默认命令离线运行，不依赖父项目缓存、本地游戏或网络：

```powershell
python -X utf8 scripts/check_7732_redemption.py --verify-only
```

需要显式重建并审阅数据版本或参数变化时：

```powershell
python -X utf8 scripts/check_7732_redemption.py
```

本次首次生成与只读复核均通过，约5秒完成40万条路线。JSON记录脚本、共享候选输入工具、两份当前审计与快照的SHA-256；任一输入变化均应重新生成并审阅，而非沿用旧百分比。

本页证明了一个“四ID皆非目标”的7732实例在声明模型内有正成功率，并给出一条合法重复救赎路线的估计表现。它不证明该路线最优，不代表所有7732都具有相同复杂度，也不等于客户端实测。后续搜索器应以目标身份和侧别等完整状态区分这些输入，再自动比较合法宏路线。
