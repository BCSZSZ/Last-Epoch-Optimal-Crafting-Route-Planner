# 全输入FP统计与自填起始FP

用户手动输入匕首全部词条后，详细实际权重路径仍显示“未计算”。复现7471、词缀79/23/85/724、目标943/18，三模式分别10.876%/16.527%/11.108%，缺失FP统计。原因是旧显示改动只覆盖等权状态策略和单一浩劫收尾；详细多步路线只算完成率，前端也固定写了未计算。

现在每条已选固定路线都用同一Completion联合状态／费用图计算FP，不依赖装备类型、输入模式或符文特例。复用真实候选池、制作暴击、希望／冰免耗、低FP保留、软失败、终止和最终耗尽仍达标的语义。确定性的条件／跳过节点折叠后，按余额递减传播访问质量，并求和同FP免费循环。每个实际执行宏按稳定路径记录进入次数、成本贡献和到达后平均FP；嵌套分支与UI合并步骤显式关联，不按数组下标硬配。

单步FP以到达该步之后为条件，包含重复，截止验收、转分支或终止；不能直接相加。成本贡献＝平均每次进入成本×期望进入次数，贡献之和等于全程平均实际FP。成功装备平均FP用同一联合图的后续成功概率加权，和全程平均分开。原生单步成本、独立反向吸收评价器和23装备种类均核对；FP统计不是客户端实测。

请求新增可选`initialFp`，省略默认48，允许0–63整数。草稿v3兼容扩展保存该值。非法输入阻止计算但不覆盖上一次合法草稿；清空恢复默认。普通／冰／血都用该起始值。等权求解、缓存、策略导出、分步占用、实际权重候选排名和下载回放都使用它，不能只改结果标题。0FP不允许开始另一动作；目标已经满足仍为100%。保留现有协议名称以兼容，报告initialFp字段决定实际预算。

固定候选的搜索预算逐条件分配，随后计算选中路线FP；FP统计不挤占其余条件的搜索机会。未穷尽搜索仍明确标注，刷新时可能找到不同候选，但同一选中路线的概率和费用可完整回放。此改动没有把有限固定候选冒充异权完整状态最优。

验证包含原297基线、截图同输入六步骤、23装备种类、简易／详细草稿、0/1/12/48/63FP、缓存升降预算、最终耗尽制作、无效输入及保存恢复。原模型和旧报告保留；BOOTSTRAP、课件、Excel、过滤器保持。
