审计日期：2026-11-03（日本时间）。当前安装为 **Last Epoch 1.5.3 / Steam build 26087601**。本报告从当前 `GameAssembly.dll` 重新读取方法字节与反汇编，不使用 Cpp2IL 占位函数体推断实现。DLL SHA-256 为 `323e9183f3bee600b6c9e1c469218b9de926e9044f2ca3d44fae8a0ec9a91464`。

产品政策补充：用户随后明确所有材料无限且不计算材料代价。下文有限仓储与材料返还是原生事实的审计记录；当前产品统一将仓储存在性按有货求值，不建设库存、价格或消耗预算输入。规则资格、支持雕文类别、暴击和FP退款仍保留。

证据编号 F1–F17 的 RVA、长度、方法 SHA-256 与关键指令均在 [机器证据](../../research/forge-fp-claims.json)。参数来自本轮重新提取的 [资源参数](../../data/game/1.5.3/resource-parameters.json)。`VERIFIED` 在本文表示已核当前本地原生路径，**不表示游戏客户端或线上服务器实测通过**。

## 1. FP 数值域：0–63，默认等权域可取 1–63

不能根据 `ItemData.forgingPotential` 的 byte 字段或元数据中的 `MaxForgingPotential=255` 常量，把 255 当作当前可持久化普通装备的 FP 上限。

- **F1 / setter：** `SetForgingPotential 0x1209C60` 在 `0x1209C93` 使用 `0x3f`，将负数归零、超过 63 的数钳到 63 后写入 FP 字段。
- **F2 / 编码：** `RebuildID 0x1206760` 在 `0x1206F98–0x1206FC7` 读取 FP，先钳至 63；将 FP 类型左移 6 位，与 FP 合并写入序列化字节。低六位为 FP，高两位为类型。
- **F3 / 解码：** `setValuesFromSerialisation 0x12130C0` 在 `0x1213FDD–0x121401D` 对字节 `&0x3f` 恢复 FP，右移 6 位恢复类型。旧序列化迁移路径也有 63 截断。
- **F4 / 初始生成：** `GenerateItems.GenerateAffixes 0x11C0D40` 调 `rollForgingPotential` 后在 `0x11C1624` 调 F1。
- **F5 / 赋能直接写入：** `EmpowerMagicRareOrExaltedCore 0x11FDCC0` 虽直接写 FP，但在 `0x11FE8DE–0x11FE90F` 先做 0–63 钳制。
- **F16 / 旧格式迁移：** `calculateForgingPotentialFromVersion0Serialisation` 的返回也截到 63。

因此本项目对**当前可持久化普通可打造装备**采用 `F=0…63`；默认评价域 `F=1…63` 等权，`F=0` 单列边界。它是产品评价约定，不是该装备自然掉落 FP 的分布，也不保证每个底材都能以全部这些预算掉落。编辑内存、未来版本及其他物品体系不由此结论覆盖。[F1–F5、F16]

## 2. 一次 Forge 的有序核

对一次合法动作，必须保留以下执行次序与联合结果，不能把费用、词缀变化、暴击和材料成本拆成互相独立的均值。

1. 读取希望等已接受的支持雕文；希望按阈值 0.25 判定免 FP。
2. 若仍未免 FP，且 `forgingPotentialType==Ice(2)`，读取资源 `iceForgingPotentialPreservationChance` 追加免 FP 判定。资源原始 float32 为 `0.30000001192092896`。
3. 执行动作本身：词缀添加／升级／封印／符文操作，以及它所调用的基础扣费核。
4. 计算主制作 ID 是否仍适合保留；混沌标记或仓储碎片检查失败会将主 ID 置为 -1。
5. 对仍有合法非负主 ID、且此次没有成功封印的路径，先检定普通暴击；普通检定失败后，血潜能 `Blood(1)` 再检定资源额外暴击。
6. 暴击路径调用额外加阶、退回该笔实际 FP 消耗并处理材料豁免；不走后述低 FP 兜底。
7. 其他实际扣费路径处理“保留 2 FP／保留 1 FP”的有序检定。
8. 完成碎片／符文、支持雕文的清理或返还及状态同步，才结束这个原子动作。

游戏资格检查仍以制作前的状态为准。扣费把 FP 降到 0，不会倒过来撤销已执行的该次动作；应先判断该次完整结果是否达标，再决定是否因耗尽而不能进入下个阶段。用户约定的“剥离失手／必要封印失败即停止”也要在完整原子动作及其后处理结束后生效。[F6、F10]

## 3. 基础 FP 费用，不是简单均匀 1–最大显示值

`applyForgingPotentialCost` 的实际逻辑：[F6]

```text
if noCost or maxBound <= 0:
    actualLoss = 0
else:
    X = NextInt(minBound, maxBound)
    if Roll(0.285):
        X = NextInt(minBound, X)
    newFP = clamp(oldFP - X, 0, 63)
    actualLoss = oldFP - newFP
```

`NextInt(lo, hi)` 上界排除；`lo==hi` 返回 lo（仍推进随机状态）。幸运成本分支的第二次抽样使用第一次结果作为上界，通常严格变小，而不是固定“再抽一次全范围取小”。

| 本项目操作 | 原生 minBound / maxBound | 未截断基础费用支持集 |
|---|---|---|
| 浩劫 | 1 / 20 | 1–19 |
| 救赎 | 1 / 20 | 1–19 |
| 剥离 | 1 / 25 | 1–24 |

`getMax…ForNonAffix` 的跳转表把 enum 9（浩劫）和 10（救赎）映射到返回 20 的分支，enum 2（剥离）映射到返回 25；对应 `getMin…` 为 1。费用核随后还需希望／冰、实际余额截断、暴击与低 FP 后处理。[F8、F9]

普通碎片费用按调用时传入的阶数参数与物品 rarity 分支，不能混淆显示 T 阶和零起始 stored tier。**同一起始 T1–T4，成功封印和失败升级的基础收费参数相同**：成功封印传 `oldStoredTier+1`；失败／普通升级先加一，再传 `newStoredTier`。新加词缀传 0。[F7、F17]

| 费用参数 tier index | maxBound（上界排除） |
|---|---:|
| 0，rarity=0 | 10 |
| 0，rarity=1 | 14 |
| 0，其他 rarity | 18 |
| 1 | 10 |
| 2 | 12 |
| 3 | 18 |
| 4 | 24 |

上述普通碎片分支 minBound=1。因而从显示 T1 开始封印或升级，对应参数 1、基础费用 1–9；T2 对应参数 2、1–11；T3 对应参数 3、1–17；T4 对应参数 4、1–23。封印成功与失败的最终消耗仍可能因暴击与退款路径而不同，但不能再把差异归因于这两者的基础收费阶数参数。[F7、F17]

## 4. 容易漏掉的低 FP 兜底：两个有顺序的 5% 阈值

当前 `Forge 0x1168790` 的 `0x116A303–0x116A416` 存在额外保留逻辑。设 `F_before` 为该笔扣费前 FP、`F_after` 为扣费后 FP、`loss=F_before-F_after`：

```text
if loss > 0:
    if F_after < 2 and F_before > 2:
        if Roll(0.05):
            F_after = 2
            loss = F_before - 2
            finish_preservation
    if F_after == 0 and F_before > 1:
        if Roll(0.05):
            F_after = 1
            loss = F_before - 1
```

先尝试保留 2；未中时才可能尝试保留 1。不是把两个 5% 相加。原始阈值为 float32 `0.05000000074505806`。例如理想独立抽样模型中，`F_before=3` 且基础成本至少为 3、无暴击退款时，终态 FP 为 2／1／0 的概率分别为 5%／4.75%／90.25%。`F_before=1` 不符合任一保留条件，`F_before=2` 只可能走保留 1 的入口。

该逻辑不限定普通／冰／血，作用于经过公共后处理且仍有实际费用的路径；成功封印和耗 FP 符文也不能漏掉。暴击退款和原本免 FP 的路径不再检定这里。它不增加 FP 到制作前以上，调整后的费用也要用于期望实际消耗统计。[F10]

## 5. 暴击资格、血潜能与材料：不能统一乘一个常数

### 5.1 当前本地代码中的必要资格

`0x1169526` 要求主制作 ID 非负，`0x1169530` 排除成功封印。先前 `0x116A219–0x116A248` 会按以下条件重置主 ID：[F10]

```text
if not shardStorage.CheckForShard(primaryId) or usingGlyphOfChaos:
    primaryId = -1
```

由此得到三个对本地代码成立的结论：

- **当前混沌路径跳过普通及血潜能暴击检定。**旧报告中“普通／混沌一概 12% 制作暴击”的表述不可直接复用。
- 普通添加／升级以及失败的绝望，仍需仓储检查满足才会进入暴击。成功绝望不会进入。
- `CheckForShard` 是仓储存在性检查，不是抽象“本次允许使用一枚碎片”的预算检查。`ClientShardStorage` 检查字典 key；其 `RemoveShard` 在减到 0 后删 key。`PopShardToModifierSlot` 已把一枚碎片移到制作栏并从仓储移除，故最后一枚碎片的边界会影响这条本地路径。`GlobalDataTracker.CheckForShard` 同样要求仓储数量大于 0。[F12–F15]

默认“材料库存不限”可令对应存储检查始终满足。后续有限**物理库存**模型要区分仓储与 modifier；用户“最多使用若干材料”的路线限制不自动等于真实游戏库存。线上权威存储实现与频次尚未实测，不能把这个本地路径事实写成已验证的线上表现。

### 5.2 检定与退款

合资格时，普通暴击阈值为 float32 `0.11999999731779099`；失败后，血潜能追加阈值为资源 float32 `0.30000001192092896`。理想独立抽样且用显示参数 0.12／0.30 表示时，总暴击率为 `0.12+(1−0.12)×0.30=0.384`。这个 38.4% 仅是该资格下的模型推导，不是每种血潜能动作的通用成功率。

暴击先调用 `AddExtraAffixTier`，再把实际 FP 损失加回，最后将报告的损失归零。外层不检查“额外升阶是否成功”的返回值才退款；即使等级阻止额外升阶，暴击退款仍发生。[F10、F11]

材料也与暴击联合：当前非成功封印的暴击分支返还主制作材料，并保留支持雕文；它不等同于希望／冰单纯免 FP。计算材料期望时不能机械地令“每次尝试均消耗 1 碎片＋1 雕文”。[F10]

## 6. 额外加阶对象不是简单“另一条均匀随机”

`AddExtraAffixTier 0x11F5AB0` 的核心选择算法：[F11]

1. 从制作后的列表收集未封印、stored tier `<4`（显示低于 T5）的对象。
2. 遇到当前主制作 ID 时，先以 0.5 阈值决定是否暂时把它移出候选池并记标志；没移出则像其他对象一样入池。
3. 若曾移出，再以 0.5 阈值或“其他池为空”的条件尝试专门升级主对象。
4. 否则在候选池中均匀选一条。
5. 选中后才检查加一阶的装备需求等级是否超过角色等级；不满足就不升级，也不改选另一条。

所以角色等级是这部分模型的真实依赖。设主词缀仍可升级，另有 m≥1 条候选，且全部等级合法，在理想独立抽样模型中：

```text
P(主词缀被额外升级) = 1/[2(m+1)] + 1/4
P(每条其他词缀被额外升级) = 1/[2(m+1)] + 1/(4m)
```

如 m=2，主词缀为 5/12，另外每条为 7/24；不能套 1/3。m=0 且主对象可升级时必选主对象。主对象制作后已达 T5 则不进入该池。所选对象的值通常重新抽 byte roll；主对象的专门路径另受 preserveRoll 参数影响。完整 roll 条件须作为状态转移保存，不能只记录阶数变化。[F11]

## 7. 精度标签与本轮边界

必须同时保留三层信息：原始 float32 参数、解析概率模型的抽样假设、求解器数值误差。当前 `RngElement.Roll(float)` 使用有限 23 位随机格点及 `q>=U`，`NextInt` 使用 32 位乘法高位桶。因此“显示 12%／30%”不是严格等于原生有限格点条件率；实际 PRNG 序列也不是在此被证明独立。产品使用独立随机抽样模型时须明示，数学上精确求解该模型也不自动等于客户端频次精确复现。

本轮已核当前静态代码，不启动游戏，不进行真实制作频次或线上服务采样。浏览器完整搜索性能、TypeScript 数值核和 Worker 取消属于后续阶段。上文程序资格及后处理差异应在规则模型审阅时突出，并以它们修正旧条件研究，不能只把旧文版本标签改为 1.5.3。
