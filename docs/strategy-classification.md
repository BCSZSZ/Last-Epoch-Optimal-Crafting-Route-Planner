# 按目标身份与装备结构生成策略模板

2026-11-03，日本时间。本次按用户最新要求重排设计：先用220／211／202／210／201／200分类，再在每类讨论具体结构与完整模板；之前的操作优先级放到子结构内部。本文是设计与讨论顺序，尚未改动线上求解器。

后续已完成[逐类结构设计与分层计算方案](strategy-hierarchy-design.md)，包含200各空栏分区、六类上层组织的局限、公共收尾及覆盖核对；以下保留分类定义和初稿。

## 一、三位编码

目标为两个不同的普通未封印词缀A、B，最终各为T7。三位数字依次为：

1. 普通未封印T7总数。
2. 其中正确目标T7数量。
3. 非T7普通未封印词缀中的正确目标数量，A／B各计一次。

本轮先讨论恰好两个T7，因此有以下六类，已覆盖该前提下的全部身份组合。T6可能计入第三位，实际tier仍需保留；封印／T8等额外槽不计入三个数字。

| 大类 | 目标身份情况 | 普通栏占用数 | 首先讨论的模板 |
|---|---|---|---|
| 220 | A、B都已是T7 | 2～4 | 已达标，结束 |
| 211 | A为T7，B在其他阶数，或反过来 | 3～4 | 四栏直接最终浩劫；三栏先合法补满 |
| 202 | A、B均存在，均非T7 | 恰好4 | 最终浩劫 |
| 210 | 一个目标T7已存在，另一目标缺失 | 2～4 | 判断能否直接补缺失目标，否则腾位再补 |
| 201 | 一个目标存在但非T7，另一目标缺失 | 3～4 | 保留已有目标身份，直接补缺失目标或腾位补词 |
| 200 | A、B均不存在 | 2～4 | 先按两个空栏／一个空栏／满四栏拆分 |

第三位为0只表示没有其他正确目标，不表示剩余两个普通位置都已填满。用户此前A／B全部缺失、T1也是垃圾的7710属于200；同样的tier串若T1已经是A，则属于201，不能只凭tier串分类。

## 二、每类再记录的结构

- 空栏数量及前缀／后缀位置。
- A、B的前后缀类型及已存在目标的实际阶数。
- 无关词缀的实际tier及所在侧，T1／T2／T3／T4／T5／T6分别保留。
- 普通封印槽是否空闲；额外槽中的ID继续参与相应原生资格及重抽排除。
- 无关对象是否具备可封、可剥、可混沌等资格，不能默认特殊词缀与普通垃圾相同。
- 实际ID、原生列表顺序、等级及明确保护条件仍由规则状态保留。

可读入口示例：`200｜空一栏｜垃圾T1｜空栏允许先补A｜普通封印槽空`。这才对应此前直接准备的7710模板。

## 三、逐类讨论模板

### 220

普通T7已经分别为A、B，其他普通位置可以是垃圾或空栏。没有roll等额外目标时直接结束，操作成功率100%，FP需求0。不为填满四栏追加制作。

### 211

A已经T7、B在T1～T6；普通栏可能三条或四条。四条时进入最终浩劫；三条时先选择合法填充，使浩劫入口具备四条普通词缀。保留补词暴击与额外加阶的不同结果，但不重复搜寻A／B身份。

### 202

两条垃圾T7加上A、B，普通四栏已满。优先讨论最终浩劫；A、B tier相同和不同的排列概率分别计算。与211可复用最终浩劫的计算模块，不把两者当成“目标身份全缺”。

### 210

先按缺失B所在侧是否有空栏拆分。可直接补B时，补B后检查是否还需要填充到四栏；没有空栏时，再按可利用垃圾T1、仅有T2～T4、无可封对象／封印槽已占用拆分。已有A身份不当垃圾处理，但浩劫可以暂时改变A的tier。

本类已有A的四栏771x应先区分：T1可直接封印；T1需搬到B侧；没有T1；已有封印。不同x仍保留具体tier，x=7属于三个T7，另开3开头类别，不塞进本轮六类。

### 201

已有A身份，但它不是T7。三栏且空位允许补B时，直接补B，再最终浩劫；空位不合侧或四栏已满时，讨论如何给B腾位。

特别区分“T1是A”和“T1是垃圾”：不能为了开槽封掉A。允许通过浩劫把T1搬到可封垃圾上，同时保留A身份；也不能把A的当前低阶误认为已经失败或需要重新获得A。

### 200

先拆成三组，暂不把所有复杂制作方式都混进同一个入口：

| 结构 | 例子（已占用普通槽的ID均非目标） | 首先讨论的路线 |
|---|---|---|
| 两个空栏 | 7700 | 两空栏是否能放入A／B；能则补齐后最终浩劫，不能则另讨论填充和腾位 |
| 一个空栏、垃圾T1 | 7710 | 合法先补A→检查／准备B侧垃圾T1→封印→补B→最终浩劫 |
| 一个空栏、垃圾非T1 | 7720～7760 | 先按垃圾tier及补词后的T1存在性继续拆分 |
| 四栏已满，含垃圾T1 | 7711、7712等 | 需要取得两个目标身份，比较剥离／补词／封印的完整顺序，不能认为一次封印就够 |
| 四栏已满，无T1 | 7732、7744等 | 先讨论开两个位置的基本路线，再逐项讨论混沌／救赎是否值得加入 |

A／B可以交换添加顺序；首先添加哪个目标由空栏侧别决定，不把名称A固定成第一步。

“混沌”“先救赎命中一个”“持续救赎双中”不再作为与220等并列的顶层分类，而是某些具体叶子的候选。困难不构成无解证明；本轮尚未决定统一禁用这些操作。

## 四、复用方向及计算范围

讨论／实现顺序为：220 → 211 → 202 → 210 → 201 → 200。先把身份齐全的收尾模板闭合，再把缺一条目标的模板闭合，最后由200获取第一条目标并复用前面的后缀。

概念上的身份进度为0→1→2；大类编号不是每一步都单向前进。浩劫可以使210变201，也可以使211变202，目标身份并未丢失。因此大类用于匹配模板，不作为完整DP状态键。

每个叶子分别登记入口条件、完整宏序列、预先声明的跳过／分支、NG条件，以及操作成功率和成功路径FP期望。继续使用[15%／65FP门槛](metric-revision-2026-11-03.md)，放弃时返回已算阶段与原因。没有覆盖的叶子登记待讨论，不当作数学无解。

本轮只确定上述分类与讨论组织；叶子模板的完整性、顺序优劣及剪枝证明仍逐类讨论，不回到任意12宏排列的默认枚举。
