# 固定路线搜索与最优性范围

> 当前政策（2026-11-08）：初始48FP内完成率为主指标；单独希望／冰＋希望／血＋希望分别求解，低于25%不推荐、达到25%推荐，没有旧15%或65FP过滤。普通等权双T7采用状态条件策略，非标准输入明确固定候选范围。见[当前算法与验收](finite48-three-profiles-20261108.md)。下文保留早期设计／测量记录。

当前实现：[23节点求解器v2](hierarchical-solver-v2.md)按结构编译完整固定模板，以操作成功率与成功路径FP评价。六类主场景不再遍历任意宏排列；超出六类的目标保留明确标注的通用语言。以下有限FP评分及宏语言v1内容作为旧基线保留。

状态：Phase 0 架构审阅稿，2026-11-03。依据[启动规范第 7–8 节](../BOOTSTRAP.md)、[宏动作契约](macro-actions.md)、[概率模型](probability-model.md)与[优化目标](optimization-objective.md)。

## 1. 搜索对象

候选是固定宏序列，不是“装备状态 → 最优下一步”的自适应策略。一个候选在全部假设 FP 上独立传播分布，最后由同一个评分配置统一比较。

宏动作参数来自有限的已支持操作、输入目标和候选词缀／槽位集合；具体生成器版本进入搜索范围标识。初始草案默认 macroStageLimit=12，允许显式配置。这个值是产品搜索预算，不是游戏规则，也不证明更长路线无用。

任何按目标缩减的候选池都需证明：未列出的填充词缀／中间身份不会通过封印、混沌、浩劫、已有 ID 排除或额外加阶改变后续结果。无此证明时，要么保留候选，要么明确写为受限候选集；不能只保留最终目标 ID 后声称覆盖整个游戏。

重复动作由宏内部停止规则吸收，不使用“每个宏最多尝试 N 次”替代 FP／资格停止。全部碎片、符文、雕文固定无限；独立显式操作次数限制、宏阶段上限和搜索时间／节点限制是不同约束。

候选生成必须包含中间准备谓词和非最终目标垃圾选择器：不能以“尚缺 B，所以浩劫不能直接完成终局”为由删除准备浩劫。必要封印的对象也不能被裁剪到 A／B 最终目标池。固定 selector 在每条分支按同一侧别／tier／垃圾／原生序规则执行，不等于临时搜索新的策略。

也不能仅依据初始侧别静态删除准备候选：添加 A 的暴击可能把原本适合的垃圾 T1 升阶。准备宏可以在仍已满足子目标的分支零次退出，在其他分支按同一固定条件继续；其价值由完整分布评价，不先验断言更优或无用。

常见模式只是候选展开优先级与基线。771x 已有 A 时优先展开“封印垃圾 T1→添加 B→最终浩劫”及需要准备浩劫的变体，省去重复 ADD_A；x=1…7 分别匹配，x=7 的三 T7 边界不得裁掉。A 身份保护不等于中间 tier 硬锁，准备浩劫仍可合法挪走 A 的 T7。

模式优先级先判真实 ID：A／B 已齐时优先 FINAL_HAVOC 基线；例如 7732 中 A@T3、B@T2，只缺阶数分配，不缺身份。不能从“两条 T7 都非目标”推断“四条词缀都非目标”。这类身份齐全入口与两目标在四个 ID 中全部缺失的入口分别登记，不强制进入救赎／封印搜身份路线。

7710／771x 不构成允许输入白名单。7732 两目标都缺或其他人脑尚未评估的起点仍进入通用生成器；只按原生资格和明确保护条件决定救赎、封印、混沌、添加及其组合是否合法。不能因为缺少 T1 封印模板或尚未做数表，静态删除整个模式。

## 2. 基线算法与数据流

1. 校验版本、起始装备、目标与限制，编译终局谓词和有限宏候选语言。
2. 以空路线作为根，展开长度不超过阶段上限的宏前缀。
3. 对各 F 保存前缀结束后的联合状态分布、已吸收成功／失败质量，以及 FP 和排序所需统计；材料仅可作独立诊断。
4. 接一个宏时组合其退出核，更新分布与奖励；所有已失败质量保持吸收。
5. 得到满足完整目标的候选后，按词典序更新当前主推荐和内部 Pareto 集合。
6. 搜索结束时同时输出候选语言／上限、节点数、未展开前沿、完成状态及可证界。

常见模式匹配仅对步骤2的展开顺序排序；通用候选仍在同一前沿中。没有命中模式返回“未覆盖的常见基线”，不是输入不合法，也不是路线不可达。

开发从小规模完整枚举开始，建立可核对的正确性基线。上线搜索再加入记忆化、状态驻留、分支定界和经证明的支配剪枝；不能先写复杂剪枝，再只用同一实现验证自身。

同一固定前缀会产生多个随机状态。下一宏必须对这整份分布使用同一个定义，不允许为分布中的每个状态各选最佳宏再拼回。后者构造的是可观察状态自适应策略。

## 3. 记忆化和状态规范化

缓存键至少含机制快照 ID、装备完整语义状态、假设 FP、当前宏／局部 subgoal／selector 及控制状态、玩家等级上下文和独立操作次数限制（若设置）。材料无限供应是模型固定政策，缓存中没有物理库存余额、价格或消耗预算；保留实际支持物／符文种类。加入准备 subgoal 和侧别垃圾 selector 时须更新宏语言及缓存语义版本，不能复用仅支持最终目标的旧核。

显示名不进入状态身份；稳定词缀 ID、原生列表顺序、roll、特殊类别、独立封印槽等会影响转移的属性进入状态键。只有已有证明的语义等价状态才能合并。相同 tier 多重集或相同终局成功率，不足以证明两个状态等价。

缓存原子核、宏核和路线前缀评价可各自独立，不向 React 或 Worker 消息复制整个搜索树。候选排序、状态编码及终端分类均确定性；改变模型或搜索语义版本即失效旧缓存。

## 4. 安全剪枝

优先实现下列可证明规则：

- 完全相同的前缀联合状态与优化所需统计分布，保留宏阶段更少或完整排序更优者。材料诊断不同不构成优劣，保留被选路线自身的诊断即可。
- 原生资格、硬保护约束、用户一次失败停止规则所禁止的动作直接排除。
- 对未吸收前沿给乐观成功界：假设所有仍存活质量以后都能免费成功。该 J 上界严格低于当前候选 J 下界时可剪枝。
- 更紧的可达性或费用下界，必须有独立证明和小模型穷举核对后才能加入。

仅“期望 FP 更低”“当前成功率更高”“每个 F 的前缀成功率都更高”都不足以支配任意后续：前缀留下的装备、阶段／局部条件和概率分布可能不同。只有对允许的全部共同后缀能保持目标序关系，才可在中间状态上做 Pareto 支配删除。材料花费更少不是本产品的剪枝或 Pareto 条件。

完整终态路线之间，可以用全部 F 的成功率及已定义排序指标保留 Pareto 候选；这个 Pareto 集合不能直接当成前缀剪枝证明。即使两个候选成功率相同，也须保留后续 tie 所需的成功条件矩与分布。

## 5. 完成状态和界

~~~text
evaluationStatus = EXACT_UNDER_MODEL | BOUNDED_NUMERICAL | ESTIMATED
searchStatus = COMPLETE | INCOMPLETE
scope = { modelId, rngModel, operationSet, macroLanguageVersion,
          macroStageLimit, candidateRestrictionId, operationLimits,
          supplyPolicy: "UNLIMITED",
          scoringConfiguration }
~~~

COMPLETE 表示该有限 scope 的所有候选已评价或被安全证明排除；只在此范围内声明最优。没有阶段上限的全局最优必须另有“更长序列无改进”的证明，不能由本搜索完成状态推出。

时间／内存／用户取消等停止搜索时，标 INCOMPLETE。已找到的可行候选可返回为“当前已找到的最佳路线”，不能标为已证明最优；无候选时返回“尚未找到”，不声称目标不可达。若前沿上界可计算，给出全局评分上界、当前候选下界与差距；缺乏有效界时相应字段为 null。

UNASSESSED 描述某个模式尚未开展评价的覆盖状态；INCOMPLETE 描述已开始但未穷尽的搜索。两者均不能映射为 IMPOSSIBLE。若只能评价几条常见路线，报告还须说明通用候选未搜索；精确算完这些路线也不能把其他起点列为不可行。

高分位与其他 tie 指标在主评分界重叠时同样影响最优证明。只有 J 的上下界相等，仍不能忽略 tie 未完成而声称排序已证实。

## 6. 浏览器与服务端执行

React 只调用统一异步规划接口，Worker 适配器管理启动、进度和取消。取消必须能中止长时间同步搜索：使用分批让出事件循环并检查取消，或终止并重建专用 Worker，不能只发一条永远没机会处理的 cancel 消息。

核心计算不导入 DOM、React 或 Worker 对象；以后 Node 适配器复用同一规则和评分模块。浏览器性能评估与 Node 使用相同快照、输入、scope 和结果口径，避免将缩小搜索范围产生的速度提升解释为平台优势。

首版并行搜索只有在分区完整性、合并排序和概率数值可复现性经过验证后启用。先把 Worker 用于保持界面响应，不承诺仅靠 Worker 就能解决状态爆炸。

## 7. 必需验证

小模型逐条枚举所有 scope 内宏序列，与优化后搜索比较主推荐、Pareto 集合和未达标分类。特意加入“均值较好但未来分布较坏”“逐预算最优路线不同”“罕见状态决定后续可达性”的反例，防止非法剪枝或自适应包络。

性能基准包含真实词缀池下的双 T7 浩劫、稀有救赎目标、必要封印／剥离前置及三类 FP。报告模型版本、搜索限制、评价精度、时间、内存、节点数、取消响应和浏览器／Node 一致性，不用玩具模型耗时承诺完整游戏性能。

7710 必须先过以下候选覆盖测试，再将剪枝加入生产搜索：

1. 侧别合适时能够生成 ADD(A)→SEAL(垃圾)→ADD(B)→最终 HAVOC，而非仅枚举升级最终目标。
2. 侧别不合时能够生成 ADD(A)→准备 HAVOC(B 侧有可封垃圾 T1)→SEAL→ADD(B)→最终 HAVOC。
3. SEAL 固定按最低原生序合格垃圾选取，不仅选 A／B；有多个合格对象时在每个分支复核同一选择器。
4. ADD 的暴击改变低阶、返还 FP 的不同结果保持独立入口，不能折成确定的 7711 或用平均 FP 代替剩余 FP 分布。
5. 明确包含必要封印失败、准备宏耗尽 FP、封印成功后无 FP 补词等失败质量。两条路线比较不加材料惩罚，完成评价也不等于已证明全局最优。

已有 A 的 771x 再增加以下覆盖：

- x=1…7 的实际四栏状态及正确／错误侧别分别建例；x=7 仍含三个 T7，不合并为双 T7 例。
- 优先路线不含 ADD_A；A 不进入垃圾封印／移除候选，浩劫临时降低其 tier 不触发未声明的硬保护失败。
- x=0 按三栏处理；封印再加 B 仍只有三栏，生成合法补栏，或在 B 能填原空栏时保留直接添加 B 的短路线。
- 7732 两目标都缺时，验证通用候选没有被模式识别器删除；未搜索到或尚未评价显示对应覆盖状态，不能变成 IMPOSSIBLE。
- 7732 两条 T7 都非目标、但 A／B 已在 T3／T2 时，优先得到 FINAL_HAVOC 基线；身份齐全判定读取实际 ID，不能因 tier 串相同而与四 ID 全非目标的复杂例合并。

## 8. 当前生产范围

v1宏库保留该底材所有可用普通碎片ID，包括非目标填充词缀；包含希望／无支持的添加、2–5阶升级及Order、一次封印、允许移除选择器、混沌至身份谓词、一次／重复浩劫和救赎、目标子集及准备选择器。它是明确有限的宏语言，不声称覆盖所有玩家可想出的控制器。

常见路线种子每种目标ID组合优先列举最多256组，全部合法ID仍保留在通用宏库中。重复相同且已满足退出条件的宏，以及第二次占用同一普通封印槽的路线按结构证明跳过。候选上界为1+ΣL^d，尚未扣除结构跳过量。

完整路线的递归状态和浩劫表在同一次评价中记忆化；当前不同路线的前缀分布尚未共享，因此复杂种子会占据明显时间。默认最多48候选、12阶段、12秒、25000状态；区间评价先用不超过6000状态，超过则尝试直接采样。总时间的65%用于候选比较，余下保留给当前采样主推荐细化。时间和内存保护不是实际游戏操作限制。

严格结构／语义校验拒绝未知字段和模型版本不符；原始输入不包含实际剩余FP、库存、价格。默认同一输入及完整有限scope确定性排序；以墙钟截断的未完成搜索可能因设备和执行时机覆盖不同候选，报告明确说明。对同一选中路线，Node和浏览器逐字段复现包括抽样种子和曲线。

最优证明目前采取保守标准：scope搜索完成、没有未评价或采样候选、主推荐J下界严格高于每个其他候选的上界才可给出范围内证明。界重叠或确切同分也保留NOT_PROVEN；不能只按点估计或tie字段宣称已证明。小型两宏两阶段Cartesian穷举与有／无剪枝结果一致，测试同时核对范围完成和证明字段。
