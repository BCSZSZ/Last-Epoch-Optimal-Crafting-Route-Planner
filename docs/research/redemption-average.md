# 两条非目标T7：单发救赎的全装备平均值

2026-11-03，日本时间。数据来自本仓库当前本地游戏1.5.3／Steam build26087601提取的[词缀定义](../../data/game/1.5.3/affixes.json)、[底材定义](../../data/game/1.5.3/items.json)及[资源清单](../../data/game/1.5.3/manifest.json)。本次重新计算这些冻结资源，并复用已有的[原生动作证据](../../research/affix-action-claims.json)；没有重新反汇编DLL，也没有做客户端频次实验。

## 结果和平均口径

在下述明确等权分布中，7732、7744四个初始普通词缀均非目标，一次救赎结束后两条T7恰好为目标A、B的平均概率为：

| 汇总 | 包含T7与目标侧别不匹配的单发零概率 | 整个总体条件化为侧别匹配后 |
|---|---:|---:|
| 565个冻结普通装备底材等权 | **0.1607936%** | **0.4032245%** |
| 23个装备类型等权，类型内底材等权 | 0.1818598% | 0.4435471% |

这些是有定义的合成平均值，**不是自然掉落分布或玩家常选词缀的平均成功率**。本次不按掉落频率给底材加权，565底材范围含冻结目录内的旧版／不自然掉落条目。完整逐池结果和输入SHA在[结构化结果](../../research/redemption-average.json)，可用[独立Python脚本](../../scripts/research_redemption_average.py)离线复现。

具体抽样约定：

1. 取一个普通底材，普通装备为23类，共565项，实际只形成38个装备类型／职业资格池组。
2. 从该底材合法、Standard、正制作权重的ID中，等权选两个不同前缀和两个不同后缀，四者都不是目标；同侧列表处理顺序也等权。
3. 四个普通位置中等权选两个为T7，其余两条为T3／T2或T4／T4。
4. 从四个初始ID以外的完整合法普通ID池中，等权选无序目标对A、B。其前后缀可能与两条T7不匹配；这些情况下“单发救赎直接双T7命中”的概率为零。
5. 不含额外封印词缀；一次救赎合法且有FP可发动。结果不计FP耗尽、后续动作或roll目标。

侧别匹配均值是对这个总体真正条件化：565底材等权总体中的匹配事件概率为39.8769549%，故0.1607936%÷39.8769549%=0.4032245%。条件化使不同底材的权重随其侧别匹配概率改变。它不是“每种T7位置仍等权，然后另选一个匹配目标对”的另一个平均定义。

7732与7744在**同一底材、ID、T7位置的这一发救赎**中相同：救赎依次改两条T7，T3／T2与T4／T4不进入身份重抽。这不表示两种物品的所有混合打造路线相同。[原生救赎证据](affix-actions-audit.md)

## 权重及顺序为何重要

重抽只选同侧、底材／职业兼容、Standard且不在当前完整ID列表中的候选。小于1的原始权重按`min(1,float32(2w))`变换；使用首个对应装备类型覆盖值。第一条写回后，第二条读取更新后的排除集合；原第一条旧ID此时可能重新成为候选。[候选和制作权重的原生审计](affix-actions-audit.md)

假设两条T7同侧，原ID按顺序为x、y，同侧合法总权重为W，目标A、B均不在起始物品上，则单发概率为：

```text
P(A,B) = wA/(W-wx-wy) × wB/(W-wA-wy)
       + wB/(W-wx-wy) × wA/(W-wB-wy)
```

若两条T7分在前后缀，A、B也各在对应侧，本发两侧互不影响排除池，概率为对应两个归一化单槽命中率的乘积。低权重目标通常显著降低具体成功率，不能用总平均替代它。

例如同一通用手套、初始ID为2／26／7／10、前两条为T7：

| 目标前缀 | 制作权重 | 单发双命中 |
|---|---|---:|
| ID4施法速度＋ID5暴击几率 | 1、1 | 0.86565098% |
| ID83药水生命转护盾＋ID503敏捷 | 约0.4、0.6 | 0.20114795% |

第一例由Fraction全终态枚举复核为`140737488355328/16257994501799281`，共289个终态，概率质量为1；与[既有独立救赎参考](7732-feasibility.md)一致。第二例来自同一个完整终态分布；精确制作权重及结果均保存在新结构化结果中。

## 聚合方法与复核

无需蒙特卡洛。对于同侧两个T7，给定旧ID顺序x、y，最终两条ID都不属于起始物品的概率是：

```text
H(x,y) = 1 - Σ[u≠x,y] wx×wu / ((W-wx-wy)×(W-wu-wy))
```

求和项对应第二次抽选返回原第一条旧ID x。第一抽一定是新ID；第二抽只有回到x时不再满足“两条都缺失于起始”。对同侧有序x、y等权平均，得到H前和H后。

令a=N前-2、b=N后-2。目标无序对总数为C(a+b,2)，六种T7位置中有一种双前、一种双后、四种一前一后。因此：

```text
E[单发成功] = (H前 + H后 + 4) / (6×C(a+b,2))
P(侧别匹配) = (C(a,2) + C(b,2) + 4ab) / (6×C(a+b,2))
```

脚本用二进制64位有限和做全量聚合；没有把它标作原生PRNG／float32累计边界的位级复现。另以不等权小模型的六种T7位置逐终态Fraction枚举核对公式，核对等权池的闭式结果，并重算上述真实手套的精确分数与质量守恒。[复现脚本与全部数学核对](../../scripts/research_redemption_average.py)

```powershell
py -3.11 -X utf8 scripts/research_redemption_average.py --verify-only
```

## 对提前剪枝的含义

这个平均值可以描述救赎双命中的量级，**不能作为所有具体输入的成功率上界，也不能据此证明整类7732或7744无解**。某些具体目标概率远高于平均值；封印、剥离、混沌、补词和浩劫的其他路线也没有包含在本次单发平均中。

也不能直接用`1/平均概率`宣称重复救赎的平均次数或FP成本：每次救赎都会改变ID和排除池，后续命中率随状态变化。[已有固定实例的顺序反例与整路线研究](7732-feasibility.md)

若产品按实用阈值隐藏低成功率路线，应明确报告阈值过滤；若要做保持最优性的安全剪枝，必须给**具体输入及其全部允许后续动作**建立成功率上界。两者都不需要把正概率写成数学上的零。
