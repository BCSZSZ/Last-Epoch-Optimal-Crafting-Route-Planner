# 路线生成算法检讨与重构方案

2026-11-06。审查对象：线上模型 `le-1.5.3-iid-b46d3015a01bbdb7`。本轮只增加诊断和设计文档，未重构或发布生产求解器。

## 结论

两次遗漏暴露了同一设计缺陷：手写完整模板家族，没有一套能系统生成合法组合、并验证覆盖范围的策略语法。动态规划／吸收链负责评价已给定程序；未生成的程序不会被评价。因此现有实现应视为有限启发式候选比较器，不能当作可靠寻找最佳路线的算法。

23个上层节点适合路由和索引。逐个节点有测试，并不能推出每个节点下的动作顺序、出口条件和固定分支已经覆盖。分类本身有用，实施把分类覆盖与策略覆盖混淆了。

原子规则与已给定路线的评价有独立研究证据，可以保留；本轮没有发现它们导致上述遗漏。修复几个反例、增加测试数量、浏览器与Node一致、Pages发布成功，均不能替代策略生成覆盖验收。此前将这些验证作为算法可靠性的主要依据，判断过于乐观。

## 当前版本仍存在的可复现遗漏

输入：普通潜能、胸甲、前缀1=T7、前缀2=T3、后缀1=T7、后缀2=T2，封印空；两个目标都是新词缀，一前一后，最终各T7，身份未填。

当前编译器生成388条模板，其中24条为按空槽交错补词家族。独立获取模块中存在T1或T2封印窗口，交错家族中仍没有这个窗口。

限定动作 `add/havoc/seal/removal`，完整评价当前生成的140条候选后，再对12条诊断程序评价：诊断程序把交错家族中的单阶准备封印替换成联合窗口，不改变预先声明的空槽分支，也没有执行途中重新优化。

## 根因与证据

1. **家族之间没有组合闭包。** [hierarchy.ts](../src/core/hierarchy.ts)同时维护取得单个身份的methods、交错补词的complete、批量腾位以及混合救赎等多套构造。新增一种封印窗口只进入methods，不会自动进入complete。这就是修完7271仍漏掉7732组合的直接原因。
2. **动作顺序和出口被藏在大模板内部。** 原“剥离取得身份”锁定目标侧的允许命中对象；能接受两侧剥离结果的批量模板又固定先腾两槽再补词，缺少按实际空槽补入目标的组合。“准备封印”又绑定填满、浩劫和一个单阶出口。上层组合只能排列整个大块，难以系统生成跨块交错顺序。此前的顺序错误属于同一问题。
3. **停止条件没有独立搜索。** 一个宏同时包含重复动作、接受出口集合、对象选择和后续程序。只枚举单阶或少数区间，没有证明这些条件足够，更没有证明其他出口集合被支配。新增T1至T2／T3／T4仍只是有限补丁。
4. **排序不能证明剪枝安全。** 当前先按启发式排序，再取48条／12秒；部分优先级甚至由中文description.includes决定。它只是运行顺序，不提供被跳过候选不可能更优的证明。本文反例的直接原因是生成遗漏，预算还会带来另一层覆盖不足。
5. **验证双方共享遗漏。** [validate_hierarchy.ts](../scripts/validate_hierarchy.ts)开关剪枝的两次plan使用同一生成器。它能检验已生成空间内的剪枝一致性，不能发现生成器没有列出的策略。112例覆盖输入标签和侧别，未建立独立的策略穷举基准。
6. **优化目标与展示必须分开审阅。** [planner.ts](../src/core/planner.ts)当前先按操作成功率及成功路径FP选primary，然后只为primary计算48FP完成率。它没有搜索最高48FP完成率。此实现符合当前保留的排序，不能据此宣传整件完成率最高；如要改变目标，应单独确定并实现。

## 改善设计

### 1. 先定义有限但可证明覆盖的策略范围

先聚焦六类双T7、两个不同普通目标、无roll要求。逐项声明允许动作、允许固定分支、最大非重复阶段数、封印／剥离NG规则，以及如何处理救赎和混沌循环。

“固定路线”继续约束整个计算：同一程序应用于全部随机出口和预算。允许的空槽／已有目标等分支必须规划前明确列出；不能把逐状态选择最优后缀的MDP策略改名为固定路线。

范围内应有完整枚举或有证明的等价归约。范围外明确未覆盖，不能使用“全部情况已设计”的措辞。

### 2. 从合法操作及目的生成程序，替代复制完整路径

让生成模块组合添加目标、填充、升级、开空槽、准备封印、改身份、收尾等基本操作。每个操作统一提供资格、状态变化、允许出口及NG语义。补词前／后封印、补满前／后封印等顺序从实际资格和阶段限制派生，不再各写一套complete。

组合层保留原子动作的可拆分性；重复只压缩明确的单符文过程，不再把开空槽与补词绑成不可插入其他动作的大块。目的用于指导生成和证明，不代替合法顺序的枚举。

重复浩劫的出口集合、封印对象的选择顺序、允许继续的出口，作为程序显式参数。所有组合位置复用同一定义。存在某个获取模块，不意味着所有含它的组合都自动正确；组合规则本身也要验证闭包。

中文说明只用于渲染。算法排序依赖类型化元数据及数学上界，不能依赖描述字符串。

### 3. 保留23类索引，详细状态和程序上下文继续参与计算

保留目标身份及原生顺序、前后缀侧别、完整阶数组合、空槽、普通词缀数、封印ID、特殊资格及FP类型。相同上层标签不自动共用概率核。

不能要求正确T7数单调增加；浩劫可能暂时降下已有正确T7。普通词缀数变化会影响封印，补词暴击会改变随后可用阶数，这些变化每一步都完整结算。

跨出口复用同一个固定后缀的评价向量；不能为每个随机出口分别挑最优后缀再拼接，除非它属于预先声明且允许的分支。

### 4. 建立独立的小规模完整枚举基准

另写参考生成器，直接从规则及明确阶段上限枚举程序顺序和局部停止集合，不调用生产compileTemplates，也不复制其家族名单。可以共享已审计的原子规则：此处检验的是搜索覆盖；原子概率正确性仍由独立数学／模拟验证。

先在不含救赎／混沌的核心范围穷尽，与生产结果逐例比较；再分别扩大动作范围。关闭剪枝的生产生成器只能作为第二种检查，不能充当独立基准。

必要验收包括：已知顺序错误、7271联合窗口、本文7732组合；所有有效上层节点的细分输入；非空停止集合组合；三类FP；T1/T2/T3/T4、重复阶数、3／4普通词缀、空槽及封印占用。分离“数值评价正确”“策略覆盖完整”“剪枝保持最优”“运行未超预算”四项结论。

### 5. 剪枝只依赖适用于完整后续的证明

保留15%操作成功率、65FP成功路径均值及48FP展示约定。最终成功概率不会超过已发生NG后的存活概率，可用于上界剪枝。费用只能使用对最终成功事件成立的下界。

前缀的“成功条件均值”不能直接作为完整路线均值下界：后续NG可能筛掉较昂贵的路径。本轮没有证明当前实现犯了此错误，它是重构中必须守住的数学约束。

对出口s保留质量p_s和费用首矩m_s，固定后缀的成功率q_s与成功费用首矩n_s共同合成：

`P = Σ p_s q_s`

`M = Σ (m_s q_s + p_s n_s)`

`成功路径平均FP = M / P`

此式要求出口状态包含使后缀独立于此前历史的全部信息。48FP完成率需要联合费用／余额核，不能只用P和均值推算。Pareto剪枝同样需要对实际入口分布或所有可能后续成立的支配证明，不能只比较上层标签或每个出口的条件均值。

“救赎普遍很差”“高阶封印通常不值”不能单独构成删除整类程序的证明。区分用户主动排除、范围限制、不可达证明和概率／费用证书，证书记录适用条件。

### 6. 性能通过局部核和验证后的缓存解决

双T7四普通槽的浩劫只重排阶数。两个其余阶数相同时有6种排列，不同时有12种。在允许其余阶数T1至T6的tier-only范围内，共21个多重集、216个有序布局；所有非空局部停止集合总计61,803个。这是局部问题计数，不是完整策略数量，尚未乘入对象选择、目标角色和其他动作。

先预计算这些局部过程的退出概率、费用联合核，再组合完整程序。同一停止集合的不同出口仍要保留，不可因集合大小相同就把后续状态合并。具体词条权重、已有ID排除和原生顺序影响救赎时，按实参补算；仅相同权重不构成完整等价关系。

先通过完整枚举基准，再预计算最终推荐。缓存一份有遗漏的候选最优解，会把遗漏固定下来。运行预算保留为交互限制，采用带上界的搜索及已验证候选作初始解；预算用尽时只能报告未搜索完，不能等同于支配删除。

## 建议执行顺序和验收门槛

1. 固定现有机制快照和本轮反例；分开记录机制、评价、生成与搜索结论。
2. 定义策略语法、允许分支及明确的完整搜索范围，补上独立参考枚举器。
3. 先让现有生产生成器在参考基准上暴露差距，再替换复制的模板家族。
4. 所有范围内输入对照通过；人为移除交错顺序／联合窗口时，测试必须能失败。
5. 逐项启用剪枝，与完整参考解比较；未有证明的删减留作启发式，不能计入完备模式。
6. 最后做预计算、浏览器性能和发布验收。低性能设备项继续按用户约定待验，不阻塞本轮算法审查。

在上述门槛通过前，当前线上推荐仍只能表示已搜索候选中的结果。本次没有通过再加一条模板来宣称根因已经解决。
