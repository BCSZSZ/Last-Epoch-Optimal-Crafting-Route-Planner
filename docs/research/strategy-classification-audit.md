# 六类策略结构的独立覆盖审计

## 分类证明与精确统计

目标是两个不同的普通未封印ID A、B，要求各为T7。本轮限定普通栏**恰好两个T7**。设r为正确目标T7数，c为普通非T7目标数。ID不能重复，故r≥0、c≥0、r+c≤2，恰好得到`220、211、202、210、201、200`六种组合，彼此互斥。[定义](../strategy-classification.md)、[重复ID和容量校验](../../src/core/validation.ts)

独立Python穷举四个有位置的普通槽`P0/P1/S0/S1`，每槽为空，或A／B／该位置的唯一垃圾X，阶数1～7；A／B各最多一次，分别核对两者侧别的四种设置。共检验163202个原始组合，保留8580个恰好两个T7且ID条件合法的结构代表。计数又与独立的位置选择／阶数组合公式逐项一致。

## 每类必须保留的决策分区

| 类别 | 完整的普通栏数量分区 | 仍需细分的结构与资格 |
|---|---|---|
| 220 | 2／3／4 | 仅在没有额外roll等目标时立即结束；不为凑满四栏制作 |
| 211 | 3／4 | 三栏要先取得合法第四词缀才能浩劫；目标非7可能为T6，救赎会改它 |
| 202 | 4 | A／B实际tier是否相同、原生位置及约束影响后续核；身份齐全不等于完整状态相同 |
| 210 | 2／3／4 | 缺失目标所在侧是否空、两空位是否都错侧、可用垃圾tier、封印是否可用 |
| 201 | 3／4 | 缺失目标的空位侧别、低阶现有目标实际tier、T1属于目标还是垃圾 |
| 200 | 2／3／4 | 两个空位能否同时放A／B、仅能先放一个、全部错侧；满栏取得两个身份需要多步腾位／重抽组合 |

“A、B分别都有一个可添加空位”还不等于能同时放入：当两者同侧且该侧仅空一格时，两者单独都可加，但不能同时容纳。两个T7占满A、B共同侧而另一侧空两格，是200两空栏的两个镜像结构；不能从“有两个空栏”直接推出能补齐目标。

## 从当前动作集得到的边界

当前七类原子动作中，产生缺失目标ID的入口只有**定向添加、混沌、救赎**。升级保ID；封印保ID并移出普通槽；浩劫只换tier；剥离只删除ID。释放一个已占用普通位置的入口只有合法封印或剥离。浩劫要求四普通栏；普通升级及其暴击追加不能造新T7，初始T7不足两条时不能完成本轮双T7目标。[`RuleEngine.eligibility/#operation/#extraTier`](../../src/core/rules.ts)、[T7资源不足校验](../../src/core/validation.ts)

这些是必要的机制约束，不自动证明某个完整模板最优。普通升级虽然不造T7，仍会改变tier多重集；若要全局删除某类前置升级，另需劣势证明。三／四T7属于其他分组，六类没有覆盖所有装备。

## 不能遗漏的组合与反例

以下均是符号化的正可能分支，脚本检查操作顺序和结构约束，不计算概率，不表示达到15%／100FP门槛。垃圾ID均互不重复；具体底材、碎片、等级和保护需在实际请求中另行校验。[逐步结构见证](../../research/strategy-classification-coverage.json)

1. **200空位全错侧的补词分支。** A／B都为前缀，两个垃圾T7已经占满前缀，后缀空两格。可以先填两个垃圾后缀至四栏→浩劫把T1移到前缀垃圾→剥离该垃圾→加A→准备浩劫→封另一前缀垃圾→加B→最终浩劫。纯救赎是另一个候选，因此不是声称所有方案都必须填垃圾。
2. **剥离与封印的组合。** 四栏200可有`剥离允许垃圾→加A→准备浩劫→封垃圾→加B→最终浩劫`。一次封印只释放一个位置，不足以直接补齐两个全缺目标；顺序和两侧容量必须逐步核对。
3. **已知目标暂降阶后的第二救赎阶段。** 200先救赎取得A7，成为210；浩劫把A降到T3，同时让缺失B所在侧的垃圾仍为T7，成为201；第二救赎保留A3，只重抽其他T6／T7，并可取得B7，成为211；最终浩劫到220。若A仅降到T6，第二救赎仍会改掉它。若明确保护要求A始终T7，该模板不合法。不能未作比较就全局禁用第二阶段救赎。
4. **200不必经过202。** 两条T7同侧时，救赎直接同时得到A7／B7，可由200到220；若有额外垃圾T6，完整救赎可在T7得到A、在T6得到B，由200直接到211。完整一发仍须处理其余所有T6／T7，不能中途停止。

### 六类不是Markov充分状态

严格反例：A／B都为前缀，以下两件都为210、三条普通词缀、tier串7710：

```text
S1 = [A7, 空前缀, X7后缀, X1后缀]   可直接添加B
S2 = [A7, X1前缀, X7后缀, 空后缀]   不能直接添加B
```

同类且普通数量相同，合法动作集已经不同，因此不能把`210`作为DP／缓存的完整状态键。另有相同201／满四栏／tier多重集7712：T1为A时不能把它当垃圾封印来开槽；T1为所需侧垃圾时则可列入候选。封印槽占用标志也不充分：封印的是缺失目标ID时，该ID不能重复添加／重抽到普通槽；而封印垃圾只是禁用再次封印。封印ID和其他实际ID必须保留。[重复ID、重抽排除及封印规则](../../src/core/rules.ts)、[完整ID候选排除](../../src/core/catalog.ts)

穷举四栏浩劫的类别边显示`210↔201`和`211↔202`，另有202／211到220；ID没有丢失，正确T7数量仍可后退。救赎还可能把已知目标ID洗掉。故上层不能硬编码为无回边的`200→202→220`。

## 算法设计判断与范围

推荐把六类用于**入口分派和模板索引**，具体入口条件及剩余宏阶段进入共享规则／宏评价模块，用完整状态或经证明充分的压缩状态缓存。211／202可以复用身份齐全的浩劫收尾；210／201复用缺一个身份的后缀模块；200调用这些已定义后缀，但不强迫所有路线逐类通关。固定路线的分支／选择器须预先声明，不能借“类别转移”改成任意逐状态重新优化的策略。[分层设计](../strategy-hierarchy-design.md)

将六类分别维护互不复用的规则与搜索会重复计算公共后缀；将六个标签直接作为上层DP状态则会丢失必要信息。两者之外的“按类分派＋共享深层模块”保留正确性和复用机会。但本次没有实现或性能基准，不能凭结构计数宣称某种实现实际快多少。8580状态的穷举证明了本轮抽象分类完备，**没有证明人工模板覆盖全部合法宏序列，也没有证明任意推荐最优**。
